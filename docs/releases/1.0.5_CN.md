# 版本 1.0.5

**发布日期：** 2026 年 5 月 22 日

## 概览

1.0.5 是一次面向常驻 daemon、数据迁移与 npm 包名的发布。这个版本新增 `wechat-daemon`，让一个工作区可以长期保持同一个微信连接，并直接从微信在 Codex、Claude Code 和 OpenCode 之间切换。daemon 会优先复用已经打开的可见 CLI；没有对应 CLI 时，会自动打开新的本地可见终端；切换时也不会关闭之前的 CLI slot。

这个版本同时把 `cli-wechat-bridge` 设为新的 npm 主包名，保留 `@unlinearity/cli-wechat-bridge` 作为兼容镜像包，把运行数据迁移到 `~/.cli-bridge`，为老用户从旧 Claude channel 路径自动迁移，并支持把微信收到的图片和普通文件保存到本地路径，交给当前选择的 CLI 读取和解析。

## 主要功能

### 常驻 daemon 模式

- 新增 `wechat-daemon` 全局命令和 `npm run daemon` 源码命令。
- 在项目目录启动一次 daemon 后，可以从微信发送 `/codex`、`/claude` 或 `/opencode` 切换当前终端。
- 切换适配器不会关闭之前的 CLI slot。
- 如果目标 CLI 已经有可见 companion，daemon 会直接切回去复用。
- 如果目标 CLI 还没有启动，daemon 会自动打开一个新的本地可见终端，并等待它连接。
- `/status` 会显示 daemon 工作区、当前活动 adapter 和各个 slot 状态。
- `/daemon-stop` 可以从微信停止常驻 daemon。
- `wechat-codex-start`、`wechat-claude-start` 和 `wechat-opencode-start` 在同一工作区发现 daemon 后，会委托 daemon 切换 CLI，而不是和 daemon 抢占运行状态。

### 短 npm 包名

- 主 npm 包名改为 `cli-wechat-bridge`。
- scoped 包 `@unlinearity/cli-wechat-bridge` 会继续作为老用户兼容镜像包发布。
- 新增双包发布脚本，可以从同一份构建产物发布主包和 scoped mirror。
- 全局安装烟测现在会先清理两个包名，避免旧全局 shim 掩盖当前安装包。

### 自动迁移到 `~/.cli-bridge`

- 默认 channel 数据目录改为 `~/.cli-bridge`。
- 新增 `CLI_BRIDGE_DATA_DIR` 作为自定义数据目录的活动配置项。
- 启动时会自动从旧 WeChat channel 目录迁移已有数据。
- 可迁移内容包括登录凭据、同步状态、上下文 token 缓存、更新检查缓存、工作区状态和入站附件。
- 新目录里已经存在的文件不会被覆盖。
- 旧 bridge lock 不会迁移，避免过期的单 bridge 状态阻塞新运行时。
- 旧 `bridge.log` 会保存为 `legacy-bridge.log`，不会和新运行日志混在一起。

### 微信入站附件

- bridge 现在会下载微信收到的图片和普通文件，并保存到 `~/.cli-bridge/inbound-attachments/<日期>/`。
- 转发给 Codex、Claude Code 或 OpenCode 的 prompt 会包含保存后的本地路径，方便 CLI 在用户要求解析时直接读取文件。
- 只有附件、没有正文的微信消息也会生成可用 prompt，不会被丢弃。
- 新增 `WECHAT_MAX_INBOUND_IMAGE_MB` 和 `WECHAT_MAX_INBOUND_FILE_MB`，用于单独控制入站下载大小限制。
- 入站消息 claim 会避免多进程重复处理同一条消息，过期 claim 会自动回收。
- 下载失败会作为 prompt 文本反馈给当前 CLI，方便它说明哪些文件没有读到。

## 修复内容

### daemon 启动清理

- `wechat-daemon` 启动前会清理过期的单 bridge lock 和 companion endpoint。
- 如果同一工作区已有独立 bridge 在运行，daemon 会请求它停止并等待清理完成。
- 如果旧 bridge 不响应优雅停止，daemon 会强制清理后继续启动。
- 独立 bridge 现在不会覆盖正在运行的 daemon；但过期的 daemon endpoint 会被自动清除。

### Windows 可见 CLI 启动

- daemon 托管的可见终端现在会通过 Windows `start` 命令启动，并正确设置窗口标题和工作目录。
- daemon 模式下的 Claude Code 与 OpenCode companion 不再提示用户手动打开第二个终端。
- daemon 会等待可见 CLI companion 完成连接后，再返回切换结果。
- 如果可见启动器超时，daemon 会清理启动器进程并返回明确状态。
- companion hello 握手后的 endpoint 状态更新会保留可见 companion PID，避免 Claude Code 或 OpenCode 已经打开后仍被 daemon 误判为连接超时。

### 微信 context 诊断

- `sendmessage` 返回 `ret=-2` 时，现在会被识别为微信 context token 过期，而不是可重试的普通传输错误。
- 日志会包含失败的发送场景和接收人，便于区分失败的是最终回复、状态更新还是 session 切换通知。
- 当缓存的 context token 过期时，bridge 会提示需要微信用户先发一条新消息来刷新上下文。

## 改进内容

- daemon 回传重要消息时会带上当前 adapter 标签，例如 `[codex]`、`[claude]` 或 `[opencode]`。
- Claude Code 和 OpenCode 的 session 切换事件可以像普通 bridge 状态一样转发到微信。
- starter 的未知参数会继续透传给本地可见 CLI，例如 `wechat-codex-start --yolo` 或 `wechat-claude-start --dangerously-skip-permissions`，但不会改变 bridge 托管的运行时配置。
- README 已补齐 daemon 模式、迁移行为、入站附件、新数据目录和 daemon CLI 参数说明。

## 升级说明

使用以下命令升级：

```bash
npm install -g cli-wechat-bridge@latest
```

升级后，请重启正在运行的 bridge、daemon 和 companion 终端，让它们加载 1.0.5 运行时。

已经使用 scoped 包名的老用户也可以继续使用：

```bash
npm install -g @unlinearity/cli-wechat-bridge@latest
```

两个包名导出的都是同一组 `wechat-*` 命令。全局环境中只需要安装其中一个。

老用户不需要手动复制文件。首次启动时，bridge 会在目标文件不存在的情况下，把旧 WeChat channel 目录中的数据迁移到 `~/.cli-bridge`。

如果你以前使用 `CLAUDE_WECHAT_CHANNEL_DATA_DIR` 自定义目录，请改用 `CLI_BRIDGE_DATA_DIR` 作为新的活动数据目录。旧变量只会作为旧数据迁移来源。

如果要长期保持多 CLI 连接，启动：

```bash
wechat-daemon
```

然后从微信发送 `/codex`、`/claude` 或 `/opencode`。

## 兼容性

本次预计没有移除任何 CLI 命令。包仍要求 Node.js `>=24.0.0`，测试工作流仍使用 Bun。

数据目录从旧 Claude channel 路径改为 `~/.cli-bridge`，但本版本已经包含老用户自动迁移。
