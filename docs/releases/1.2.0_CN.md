# 版本 1.2.0

**发布日期：** 2026 年 9 月 21 日

## 概述

版本 1.2.0 通过带认证的本地 IPC 接口向外部程序开放 daemon，新增 `/all` 命令将同一段提示词广播给全部已启动的 CLI，微信派发任务期间显示原生「正在输入」状态，并让回复投递与微信官方机器人客户端的行为对齐。产品网站围绕原生双向工作流重构，协议声明也在整个代码库全面强化。自 1.1.8 以来共 154 个文件变更，新增 5,371 行，删除 1,164 行。

## daemon IPC（外部程序接入）

`wechat-daemon` 与 `wecom-daemon` 现在开放带 token 认证的本地 IPC 接口。网页面板、脚本或自建机器人前端等外部工具可以像聊天消息一样驱动 daemon：

- `forward_input` 将文本按与入站聊天完全一致的处理规则下发给任意 CLI：忙碌时拒绝、有待审批或补充输入时等待、Codex 本地任务期间自动排队。同一 CLI 的请求顺序执行，回复始终发回所属会话，输入被拒绝或失败时自动回滚任务状态与当前 CLI 选择。
- `send_text` 借用 daemon 的消息通道发送文本，context 值经过类型校验。

接口语义见 `docs/development.md`。

## `/all` 广播命令

在微信或企业微信中发送 `/all <提示词>`，即可将同一段提示词同时下发给所有已启动的 CLI。未启动的 CLI 会在确认消息中列为跳过，并提示对应的启动命令；若任一已启动的 CLI 正忙——正在执行任务、等待审批、等待补充输入或存在排队消息——则整条广播取消并明确告知原因，不会只送达一部分。各 CLI 的回复仍带各自名称前缀，当前使用的 CLI 保持不变。

## 微信「正在输入」状态

CLI 处理微信派发的任务期间，聊天窗口会显示原生「对方正在输入…」状态，以 5 秒心跳保持，并在回复送达、任务失败或 daemon 关闭时取消。typing 凭证按联系人从微信官方配置端点获取，带 24 小时内随机刷新与指数退避重试；无凭证或发送失败时整体静默降级，消息收发不受影响。相关钩子位于通道 driver 上，其他通道不受影响。

## 回复投递改进

- 较长的回复现在作为一条完整消息发出，不再按 1,200 字符拆分，与微信官方机器人客户端在单次 sendmessage 调用中发送完整文本的行为保持一致。若服务器拒收超长消息，既有的重试、日志与待发队列机制仍会记录失败，回复不会无声丢失。
- 待发队列只保留值得送达的内容——最终回复、审批与补充输入请求、失败提示；本地输入镜像、通知与状态切换类消息不再排队。条目超过 30 分钟自动过期，积压上限 10 条，因此 token 中断后重连最多补发最近的重要回复，不再重放数小时前的历史消息。

## 产品网站重构

GitHub Pages 产品站围绕微信或企业微信与本地 CLI 会话之间的原生双向工作流重构：中英文路由、Channel → Bridge → CLI 交互式架构图、能力与安全边界说明、支持通道切换的启动命令轮换器，以及适配响应式与减少动态效果偏好的真实记录轮播。站点指标每日刷新，包版本变化时自动重新部署。

## 重要说明与升级

Node.js 最低版本保持 22.13.0；使用 Pi 适配器需要 22.19.0 或更新版本。升级主包：

```bash
npm install -g cli-wechat-bridge@latest
```

作用域包用户升级：

```bash
npm install -g @unlinearity/cli-wechat-bridge@latest
```

升级后请重启正在运行的 bridge、daemon 和可见 CLI 进程。IPC 接口在运行中的 daemon 上默认启用；endpoint 与 token 位置见 `docs/development.md`。无需迁移步骤。
