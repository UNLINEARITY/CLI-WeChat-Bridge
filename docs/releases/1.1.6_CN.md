# 版本 1.1.6

**发布日期：** 2026 年 8 月 31 日

## 概览

1.1.6 将 bridge 通用核心与微信专属代码分离，适配 Codex CLI `0.149.1` 之后出现的上游 thread 行为，并在微信 context token 不可用时保留回复。本版本同时调整 emoji 绑定归属，将 Node.js 最低版本降至 `22.13.0`，并记录完整的 Linux npm 生命周期脚本授权流程。

## Bridge Core 与微信通道分离

新增的 `src/core` 层包含通道无关的会话与附件类型、`BridgeChannelPort` 接口、控制命令解析、入站消息路由、事件转发和共享文本工具。`src/channels/wechat` 包含微信消息转换、最终回复格式化、面向传输的事件处理、`WechatChannelPort` 和待发送队列。微信 context token 作为 opaque channel state 传递，core 不解析该字段。

direct bridge 与 daemon 现在共用 `/status`、`/resume`、`/new`、`/stop`、`/reset`、`/confirm`、`/deny`、`/answer` 的标准语法，并使用相同路由顺序：鉴权、控制命令、待审批、待结构化输入、延迟输入、busy 状态和任务分发。daemon emoji binding 仍是 core router 之前的独立层。两种运行模式共用输出、最终回答、审批、用户输入请求、本地输入镜像、session/thread 切换、完成、失败和关闭事件的转发协议。公开 CLI 命令名、状态文件位置、消息格式和 adapter 接口保持不变；兼容导出保留现有 `src/bridge` 导入路径。Fake Channel 测试验证 core，没有增加第二个生产通道。

## Codex 上游兼容

### 上游行为变化

Codex `rust-v0.149.1` 不包含 TUI 自动会话标题生成。上游改动 `#40492` **Generate descriptive TUI thread titles** 在后续版本加入该功能。标题生成会启动带有 `ephemeral: true`、`threadSource: feature(system)` 的隐藏 helper thread。app-server 的 `thread/started` 通知包含完整 thread 元数据，而 `thread/status/changed` 只包含 `threadId` 与 `status`。

旧 bridge 跟随当前工作区中所有进入 idle 的 thread。上游标题 helper 出现后，隐藏 thread 会先覆盖共享 thread ID，随后根 thread 的状态再次触发切换。运行日志中的实际表现包括重复 thread 切换通知、微信任务被中断，以及 bridge 跟随 helper thread 后本地输入镜像缺失。

### Thread 校验与 resume

1.1.6 使用 `thread/read` 解析未知状态 ID。本地跟随要求 ID 精确匹配、cwd 一致、没有 parent thread 且 `ephemeral !== true`；`thread/started` 与启动恢复使用相同根 thread 条件。bridge 在启动时记录已安装 Codex 版本。Codex CLI `0.149.1` 与 `0.151.0` 已验证，后续版本仍可启动，超出已验证范围时写入日志。

微信 `/resume` 按目标校验、app-server `thread/resume`、可见客户端切换、共享 thread 提交的顺序执行。可见切换失败时保留原 thread。bridge 自己触发的 resume 回放通知在五秒稳定期内被抑制，真实本地 turn 到达后解除。headless 本地 thread 切换后立即执行去重订阅，本地 prompt 继续在最终回答前产生 `mirrored_user_input`。

微信发起的 turn 完成后，弱 `thread/status/changed`、`thread/started` 和 session fallback 信号在 150 毫秒内被忽略。真实本地 `turn/started` 或 user-message 事件会立即解除该限制。

Codex 本地 thread 通知仅在最终回答后的前 500 毫秒被抑制。之后发生的本地 `/resume` 会转发到微信，并清除五分钟有效的数字 resume 快照。该行为替换了会隐藏真实本地 thread 切换的宽泛抑制。

### 事件顺序与诊断

direct bridge 与 daemon 为每个 runtime 使用独立 Promise 链，按到达顺序处理 thread、状态、最终回答和生命周期事件。单个 handler 失败时记录 `event_forward_failed`，后续事件继续执行。Codex fatal 诊断保留 app-server 最后六条非空日志，最长 500 字符；微信侧 fatal 消息不包含内部 app-server 日志尾部。

## 微信回复恢复

`sendmessage ret=-2` 将收件人 context 标记为 stale，或当前没有缓存 context token 时，direct bridge 与 daemon 会把未发送文本写入 `~/.cli-bridge/workspaces/<workspace-key>/pending-wechat-messages.json`。bridge 重启后会重新读取该文件。下一条微信入站消息刷新收件人 context 后触发顺序补发，每条记录仅在发送成功后删除。

微信发送诊断新增 `wechat_send_started`、`wechat_send_completed` 和 `wechat_send_timeout`，记录 context、收件人、尝试次数和耗时。这些记录用于区分模型输出耗时、微信传输耗时、重试和 stale context 恢复。

## 行为变更：Standalone Emoji 绑定

standalone bridge 之前会加载 daemon emoji binding store，改写以已绑定 emoji 开头的消息，并拦截 `/bind`、`/unbind` 和 `/bindings`。对于固定连接单一 adapter 的 bridge，这会使 emoji 和类似绑定命令的文本在到达当前 CLI 前被消费。

1.1.6 从 standalone bridge 移除 emoji 绑定解析与管理，输入原样交给当前 CLI。`wechat-daemon` 继续提供 emoji 命令解析、adapter 切换、`/bind`、`/unbind`、`/bindings` 和现有绑定数据。需要微信 emoji 绑定的用户应使用 daemon 模式。

这项修改移除了 1.1.0 引入的 standalone emoji 绑定流程。daemon emoji 绑定流程和已保存绑定保持不变。

## 安装与升级

Node.js 最低版本为 `22.13.0`，入口按完整 major、minor、patch 比较。Node.js `22.12.x` 被拒绝，`22.13.x`、23 和 24 可用。`CLI_BRIDGE_SKIP_NODE_CHECK=1` 可跳过入口检查。CI 在 Ubuntu、macOS 和 Windows 上运行 Node.js `22.13.0` 与 Node.js 24。OpenCode 支持范围保持 `>=1.18.0 <2.0.0`。

较新 npm 在 Linux 上可能完成安装但阻止 `cli-wechat-bridge` postinstall 与 `node-pty` install 脚本。该状态会影响依赖 PTY 的路径，macOS/Linux 的 `spawn-helper` 权限修复也不会执行。干净安装命令为：

```bash
npm uninstall -g cli-wechat-bridge
npm install -g cli-wechat-bridge@latest --allow-scripts=cli-wechat-bridge,node-pty
```

用户级持久授权命令为：

```bash
npm config set allow-scripts=cli-wechat-bridge,node-pty --location=user
npm install -g cli-wechat-bridge@latest
```

安装命令必须保留 package 名。只运行 `npm install -g --allow-scripts=...` 会使 npm 把当前目录作为待安装 package，并可能返回 `ENOENT /home/<user>/package.json`。安装后运行 `wechat-daemon --doctor`，确认 `node-pty` 已加载。

升级主包：

```bash
npm install -g cli-wechat-bridge@latest
```

现有 scoped 包用户使用：

```bash
npm install -g @unlinearity/cli-wechat-bridge@latest
```

无需迁移运行时数据。升级后重启正在运行的 daemon、bridge 和可见 CLI。
