# Version 1.1.5

**Release Date:** August 24, 2026

## Overview

Version 1.1.5 completes bidirectional session recovery for all four supported local CLIs. WeChat can now list and restore recent Codex, Claude Code, OpenCode, and Pi conversations in the daemon or direct-launcher workflow, while session changes made in the visible local TUI continue to move the WeChat bridge to the same conversation. This release also completes the launcher migration announced in 1.1.4 by removing the deprecated `wechat-*-start` aliases.

## Bidirectional `/resume`

### Shared WeChat workflow

- `/resume` lists the eight most recent root threads or sessions for the daemon or bridge startup directory.
- `/resume <number>`, a complete ID, or a unique ID prefix restores an item from that list. Numbered selections remain valid for five minutes and are invalidated when the local TUI moves to another conversation.
- Recovery is limited to the current working directory. Busy turns, pending approvals, pending user-input requests, and targets that are still active are rejected instead of being silently detached.
- If the user changes the local conversation while a WeChat-owned task is running, the old task is interrupted and settled before the bridge follows the new local conversation.

### Codex

Codex history is discovered and validated through its app-server rather than by treating rollout files as the primary control surface. The bridge checks the target with `thread/list`, `thread/read`, and `thread/resume`, excluding foreign-workspace, subagent, ephemeral, and active threads. A token-authenticated localhost supervisor replaces only the visible Codex TUI child while keeping the shared app-server alive; shared state changes only after the target client starts successfully, and a failed switch attempts to restore the previous visible thread. If the daemon still owns the Codex slot after its visible window was closed, a targeted WeChat resume reopens the visible client first.

### Claude Code

Claude Code recovery uses its structured hook lifecycle. The bridge sends an exact `/resume <UUID>` to the current visible PTY and waits for `SessionEnd(reason=resume)` followed by the matching `SessionStart(source=resume)` before accepting the switch. Recent same-directory root sessions are read from Claude metadata and bounded transcript windows; sidechains, empty sessions, foreign directories, and sessions reported active in another Claude process are excluded. Local picker and `/resume` changes follow the same hook path back to WeChat.

### OpenCode and Pi

OpenCode recovery now waits until the visible TUI has actually selected the requested session before committing shared state. A temporary, randomly authenticated route reporter observes local picker and new-session navigation without modifying the user's permanent OpenCode configuration. Pi restores through its native visible extension with repeated idle, file, session-ID, and cwd validation. Local Pi turns now forward both the mirrored input and their final reply or error to WeChat, so the phone and terminal observe the same complete exchange.

## Breaking Change: Removed `wechat-*-start`

The one-release deprecation period has ended. These commands are no longer published:

- `wechat-codex-start` → use `wechat-codex`
- `wechat-claude-start` → use `wechat-claude`
- `wechat-opencode-start` → use `wechat-opencode`
- `wechat-pi-start` → use `wechat-pi`

The four direct commands already provide the same smart-launcher behavior: credential validation, same-directory daemon delegation, transient runtime provisioning when no daemon exists, visible CLI startup, and passthrough of native CLI arguments. Internal npm development scripts such as `codex:start` are unchanged.

## Upgrade Notes

Upgrade the primary package with:

```bash
npm install -g cli-wechat-bridge@latest
```

Existing scoped-package users can continue with:

```bash
npm install -g @unlinearity/cli-wechat-bridge@latest
```

After upgrading, restart every running daemon, bridge, and visible CLI so the new resume control paths are loaded. Update scripts, shortcuts, and shell history that still call a removed `wechat-*-start` command. No runtime data migration is required.

## Compatibility

- Node.js `>=24.0.0` remains required; the source and test workflow continues to use Bun.
- OpenCode support remains `>=1.18.0 <2.0.0`.
- The Codex recovery path was validated with Codex CLI `0.149.1`, and the Claude Code path with Claude Code `2.1.235`.
- The release does not modify user-owned Codex, Claude Code, OpenCode, or Pi source/configuration files.
