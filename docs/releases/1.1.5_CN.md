# 版本 1.1.5

**发布日期：** 2026 年 8 月 24 日

## 概览

1.1.5 完成四个本地 CLI 的双向会话恢复。无论使用 daemon 还是直接启动器，微信现在都可以列出并恢复 Codex、Claude Code、OpenCode 和 Pi 的最近对话；电脑端在可见原生 TUI 中主动切换后，微信 bridge 也会继续跟随同一个对话。本版本同时兑现 1.1.4 的启动器迁移计划，正式删除已经完成弃用周期的 `wechat-*-start` 别名。

## 双向 `/resume`

### 统一微信流程

- `/resume` 列出 daemon 或 bridge 启动目录最近 8 个根 thread/session。
- `/resume <编号>`、完整 ID 或唯一 ID 前缀均可恢复列表中的目标。编号快照有效期为 5 分钟；电脑端切换到其他对话后，旧编号立即失效。
- 恢复范围严格限制在当前工作目录。当前 turn 仍在运行、存在待审批或待回答请求、或者目标仍处于 active 状态时，bridge 会明确拒绝切换，不会静默脱离原会话。
- 如果微信任务运行期间用户在电脑端主动切换，bridge 会先中断并结算旧微信任务，再跟随新的本地对话。

### Codex

Codex 历史 thread 通过 app-server 发现和校验，不再把 rollout 文件扫描当作主要控制面。bridge 使用 `thread/list`、`thread/read` 和 `thread/resume` 检查目标，并排除跨工作区、subagent、ephemeral 与 active thread。带随机 token 鉴权的 localhost supervisor 只替换可见 Codex TUI 子进程，持久 app-server 保持运行；目标客户端稳定启动后才提交 shared state，切换失败时尝试恢复原可见 thread。daemon 仍持有 Codex slot、但可见窗口已经关闭时，微信指定恢复目标会先重新打开可见客户端。

### Claude Code

Claude Code 通过结构化 Hook 生命周期确认恢复。bridge 向当前可见 PTY 提交精确 `/resume <UUID>`，并等待 `SessionEnd(reason=resume)` 与匹配的 `SessionStart(source=resume)` 到达后才接受切换。最近同目录根 session 来自 Claude metadata 与 transcript 头尾的有界读取；sidechain、空 session、跨目录 session，以及被其他 Claude 进程报告为 active 的目标不会进入恢复路径。电脑端 picker 与 `/resume` 也通过同一 Hook 链路反向同步微信。

### OpenCode 与 Pi

OpenCode 恢复会等待可见 TUI 真正选中目标 session，再提交 shared state。一次性、随机鉴权的 route reporter 观察本地 picker 与新 session 导航，不修改用户永久 OpenCode 配置。Pi 通过原生可见 extension 恢复，并在执行时重复校验 idle、文件、session ID 与 cwd。Pi 本地 turn 现在会把镜像输入及对应最终回复或错误完整转发到微信，使手机和终端看到同一条完整对话。

## 破坏性变更：移除 `wechat-*-start`

一版弃用周期已经结束，以下命令不再发布：

- `wechat-codex-start` → 使用 `wechat-codex`
- `wechat-claude-start` → 使用 `wechat-claude`
- `wechat-opencode-start` → 使用 `wechat-opencode`
- `wechat-pi-start` → 使用 `wechat-pi`

四个直接命令已经提供相同的智能启动器行为：微信凭据校验、同目录 daemon 委托、无 daemon 时创建 transient runtime、打开可见 CLI，以及透传底层 CLI 参数。`codex:start` 等内部 npm 开发脚本不受影响。

## 升级说明

升级主包：

```bash
npm install -g cli-wechat-bridge@latest
```

现有 scoped 包用户继续使用：

```bash
npm install -g @unlinearity/cli-wechat-bridge@latest
```

升级后请重启所有正在运行的 daemon、bridge 和可见 CLI，使新的恢复控制链路生效。脚本、快捷方式或命令历史中仍使用 `wechat-*-start` 的地方，需要替换为对应直接命令。无需迁移运行时数据。

## 兼容性

- 仍要求 Node.js `>=24.0.0`，源码与测试工作流继续使用 Bun。
- OpenCode 支持范围仍为 `>=1.18.0 <2.0.0`。
- Codex 恢复路径已在 Codex CLI `0.149.1` 验证，Claude Code 路径已在 Claude Code `2.1.235` 验证。
- 本版本不会修改用户自己的 Codex、Claude Code、OpenCode 或 Pi 源码和永久配置。
