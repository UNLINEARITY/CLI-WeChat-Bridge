# Version 1.1.0

**Release Date:** May 27, 2026

## Overview

Version 1.1.0 introduces internationalization (i18n) with Chinese as the default language, real-time Claude thinking forwarding to WeChat, a critical fix for Claude auto-approval delivery failures, and several reliability improvements including Codex process tree cleanup and cross-platform bridge diagnostics.

## New Features

### Internationalization (i18n)

- Lightweight i18n system with no third-party dependencies.
- Chinese is now the default language for all user-facing messages.
- Switch to English with `CLI_BRIDGE_LANG=en` environment variable.
- `t(key, params?)` lookup function with `{param}` interpolation.
- Covers: bridge/daemon welcome messages, hook health check warnings, PTY fallback warnings, spawn diagnostics, and emoji binding management messages.
- Falls back to English catalog when a key is missing from the active locale.

### Claude Thinking Forward

- Real-time forwarding of Claude's thinking process to WeChat.
- Polls Claude's transcript file (JSONL) at 800ms intervals to extract thinking blocks.
- Thinking content is forwarded with a "思考:" prefix.
- Disabled by default; enable with `CLI_BRIDGE_THINKING_FORWARD=1` env var or `enableThinkingForward: true` in account.json.
- Watcher starts on user input / SessionStart and stops on turn completion.

### Multi-Approval Batch Commands

- Queue-based approval architecture replaces single-value storage.
- Multiple simultaneous permission requests are queued instead of overwriting each other.
- `/confirm`, `/yes`, bare "confirm"/"yes" batch-confirms all pending approvals.
- `/deny`, `/no`, bare "deny"/"no" batch-denies all pending approvals.
- Bare text approval commands now work for all adapter types (previously Claude-only).

### Emoji Bindings in Single Bridge Mode

- `/bind`, `/unbind`, `/bindings` commands now work in standalone single bridge mode (previously daemon-only).
- Startup welcome message shows available commands and current bindings.
- Malformed `/bind` or `/unbind` commands return usage hints instead of being forwarded to the adapter.

## Bug Fixes

### Claude Auto-Approval Delivery Failure (Critical)

- Fixed: auto-approval for non-Bash tools (WebFetch, Read, Write, etc.) fails silently — bridge logs "auto-approved" but the TCP response never reaches Claude Code, leaving Claude stuck at the terminal permission prompt with no WeChat notification.
- Root cause: Claude hooks use one-shot TCP connections; if the socket closes before delivery, the response is lost.
- Fix: save the last auto-approved payload; when a `permission_prompt` Notification arrives with no pending approval, fall back to forwarding the request to WeChat for manual approval.

### Broadened Auto-Approval Policy

- All non-Bash tool permissions (WebFetch, Read, Write, Glob, Grep, etc.) are now auto-approved, not just a hardcoded subset.

### Codex Process Tree Not Killed on Shutdown (Windows)

- `child.kill()` only signals the immediate process; Codex app-server child processes survived daemon shutdown.
- Replaced with `killProcessTreeSync()` using `taskkill /T /F /PID` on Windows and `process.kill(-pid)` on Unix.

### Cross-Platform Bridge Failure Diagnostics

- Hook script stderr now redirects to a log file instead of /dev/null.
- 15-second hook health check timer emits diagnostic warning to WeChat if no hook events arrive.
- PTY spawn falls back to `child_process.spawn` when node-pty fails, with platform-specific diagnostics.

## Upgrade Notes

Upgrade with:

```bash
npm install -g cli-wechat-bridge@latest
```

After upgrading, restart any running bridge, daemon, and companion terminals so they load the 1.1.0 runtime.

Existing scoped-package users can keep using:

```bash
npm install -g @unlinearity/cli-wechat-bridge@latest
```

## Compatibility

No new data migration is required. The package still requires Node.js `>=24.0.0`, and the source/test workflow still uses Bun.
