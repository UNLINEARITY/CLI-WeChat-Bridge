# 版本 1.0.7

**发布日期：** 2026 年 5 月 26 日

## 概览

1.0.7 是一次面向 daemon 稳定性、fresh session 启动和文档整理的修复版本。它强化了 `wechat-daemon` 的切换逻辑：当可见 CLI 没有成功连接时，不再污染当前 active terminal；Codex 可见端在 endpoint 文件丢失后也能重新发布 endpoint 并恢复连接；daemon 启动时即使 `daemon-endpoint.json` 缺失或指向错误进程，也会扫描并清理同工作区残留的 daemon peer。

本版本还让 Claude Code 和 OpenCode 的启动器默认创建新会话，清理不再属于 daemon-first 架构的旧运行路径，并把配置、排查、开发和贡献说明拆分到独立文档中。

## Daemon 可靠性修复

### 更安全的 adapter 切换

- `wechat-daemon` 现在只有在可见 CLI 成功连接后，或显式禁用可见端启动时，才会激活请求的 adapter。
- 如果 `/codex`、`/claude` 或 `/opencode` 无法连接可见 CLI，daemon 会反馈激活失败，并保留上一个 active adapter。
- 切换日志新增 `activated`、`previous_active` 和 `session_start_mode` 字段，便于直接从 `bridge.log` 诊断运行时问题。
- 已存在的 Codex slot 在打开可见端前会重新发布 local companion endpoint，避免 endpoint 文件被删除后 `codex-remote-client` 直接退出。

### 启动清理和进程接管

- daemon 启动时会清理同工作区仍在运行的 `wechat-daemon` peer 进程，即使 `daemon-endpoint.json` 不存在或指向错误 pid。
- endpoint 清理现在会同时清理每个 daemon adapter 的 workspace companion endpoint。
- 强制清理会避开当前进程和父进程，并且只有在 endpoint pid 能确认是 daemon 进程，或已经收到 shutdown ACK 时才会强制停止。
- cleanup 单元测试现在注入 daemon log 函数，避免 fake 测试 pid 写入真实的 `~/.cli-bridge/bridge.log`。

## 会话启动改进

### Claude Code 和 OpenCode 默认 fresh session

- `wechat-claude-start` 和 `wechat-opencode-start` 现在默认请求 fresh session，不再静默恢复旧 shared-session 状态。
- daemon 创建 Claude Code 和 OpenCode slot 时也默认使用 fresh session，除非正在复用已经连接的可见客户端。
- 对 Claude Code 和 OpenCode 来说，同工作区启动请求在需要 fresh session 时可以替换现有 companion-bound bridge。
- Claude Code fresh start 会忽略保存过的 resume id，避免误恢复旧 transcript。
- OpenCode fresh start 会通过 SDK 创建新 session，并把目标目录和 active session route 一起传给原生 attach client。
- OpenCode 可见端 session 选择增加短暂重试，使 TUI 更可靠地跟随 daemon 选中的 session。

### Claude workspace trust prompt 处理

- Claude Code 启动时会尽量在 `.claude.json` 中标记当前 workspace 已信任。
- 如果 Claude 启动阶段仍输出 workspace trust prompt，bridge 会在用户输入开始前自动确认。
- 一旦 WeChat turn 已经开始，自动确认逻辑会禁用，避免把普通输出里相似的文本误判为启动提示。

## 清理与文档

- 删除旧 standalone Claude bot、旧 Codex panel IPC 文件和未使用的 media transport 抽象。
- 移除当前运行路径不再直接 import 的 `@anthropic-ai/sdk` 和 `ajv-formats` 依赖。
- 为源码检查显式补充 Node 类型依赖。
- 新增 `CONTRIBUTING.md`，说明 issue、PR、开发、测试和发布流程。
- README 重新聚焦用户启动路径，并把运行配置、问题排查和开发说明拆分到 `docs/configuration.md`、`docs/troubleshooting.md` 和 `docs/development.md`。
- README 新增 daemon 多 CLI 示例截图。

## 升级说明

使用以下命令升级：

```bash
npm install -g cli-wechat-bridge@latest
```

升级后，请重启正在运行的 bridge、daemon 和 companion 终端，让它们加载 1.0.7 runtime。如果旧版本残留了 daemon 进程，在同一工作区重新启动 `wechat-daemon` 时现在应能自动清理。

已经使用 scoped 包名的老用户也可以继续使用：

```bash
npm install -g @unlinearity/cli-wechat-bridge@latest
```

两个包名导出的都是同一组 `wechat-*` 命令。全局环境中只需要安装其中一个。

## 兼容性

本版本不需要新的数据迁移。包仍要求 Node.js `>=24.0.0`，源码和测试工作流仍使用 Bun。

旧 standalone Claude bot 和旧 Codex panel 内部实现已经从源码树移除。发布包面向用户的命令仍聚焦 Codex、Claude Code、OpenCode 和 daemon 工作流。
