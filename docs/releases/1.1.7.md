# Version 1.1.7

**Release Date:** September 1, 2026

## Overview

Version 1.1.7 adds a first-class WeCom channel backed by the official smart-bot WebSocket SDK. It also hardens Claude Code remote input delivery, Windows process identity checks, and Windows WeChat QR login. The README now uses a repository-owned static Star History image generated by GitHub Actions instead of the restricted hosted stargazer endpoint.

## WeCom Smart-Bot Channel

The package now includes `@wecom/aibot-node-sdk@1.0.7` and the public commands `wecom-setup`, `wecom-check-update`, `wecom-daemon`, `wecom-codex`, `wecom-claude`, `wecom-opencode`, and `wecom-pi`. `wecom-setup` validates the Bot ID and Secret through the official WebSocket connection, displays a one-time pairing code, and stores the paired operator identity after the operator sends `/pair <code>` in a direct chat.

WeCom direct launchers and daemon use the same adapter slots, command grammar, approvals, session recovery, and local companion flow as the WeChat channel. The transport supports internal direct chats and internal groups, ordered text and streaming replies, inbound image/file/video download with decryption, and outbound text and media. WeCom credentials, downloaded attachments, and inbound claims are isolated under `~/.cli-bridge/wecom`; workspace locks and adapter state remain shared so one workspace cannot be controlled by two remote channels at the same time.

Each WeCom Bot ID may have one active WebSocket connection. External groups, customer groups, callback-based applications, and private WeCom deployments are outside the supported scope. The official SDK's large-upload acknowledgement delay remains a known limitation; the bridge sends attachments sequentially and reports the file name and failure type instead of silently dropping the transfer.

## Claude Code Remote Input

Claude Code input now waits for the interactive `SessionStart` signal before writing a remote prompt into the PTY. The bridge submits bracketed paste followed by Enter after a short delay, then retries Enter at 200 ms, 500 ms, and 1 s until the matching `UserPromptSubmit` hook arrives. Retries are cancelled when the prompt is accepted, the turn completes, the task is interrupted, the session is reset, or the process exits; invalid resume recovery also rebuilds the interactive adapter before retrying.

This closes the Windows path where a WeChat or WeCom prompt could remain in the visible Claude composer without being submitted, while preserving local keyboard input and hook-based approvals.

## Windows Process Checks and CI

Windows bridge ownership checks now query the recorded PID directly through `Win32_Process -Filter` instead of enumerating every process. The command-line bridge filter and PID-reuse protection remain in place, while cold-start and CI checks avoid the previous full-process scan. The process-identity regression test has a 12-second timeout, and the CI matrix names all six checks by operating system and Node.js version.

## WeChat QR Login

`wechat-setup` keeps compact `small` QR rendering as the default, including on Windows, and adds `--qr-mode normal` for terminals that render compressed Unicode blocks incorrectly. Login now requires an interactive terminal, checks the rendered QR width against the terminal, and prints a short-lived browser URL when the QR cannot safely be displayed. The URL is written only to the interactive terminal and is not sent through runtime logs or non-TTY output.

## Static Star History

The repository now contains `.github/workflows/star-history.yml`, which runs daily and through `workflow_dispatch` with `contents: write`. It invokes the pinned `narayann7/star-history-action` renderer, writes a fixed `assets/star-history/star-history.png` path, and updates the README marker block. The README no longer depends on `api.star-history.com`; the first workflow run must be dispatched after the workflow is available on GitHub to generate the image.

## Documentation and Upgrade

README, architecture, development, configuration, troubleshooting, and the release index now describe both WeChat and WeCom entry points, state files, limits, source-mode commands, and channel-specific behavior. The historical command audit is explicitly marked as a 1.1.5-era snapshot so it is not mistaken for the current command inventory.

The minimum Node.js version remains `22.13.0`. Upgrade the primary package with:

```bash
npm install -g cli-wechat-bridge@latest
```

Existing scoped-package users can upgrade with:

```bash
npm install -g @unlinearity/cli-wechat-bridge@latest
```

Restart running bridge, daemon, and visible CLI processes after upgrading. WeCom users should run `wecom-setup --check` after changing Bot credentials or pairing settings.
