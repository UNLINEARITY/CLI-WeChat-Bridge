# Version 1.2.1

**Release Date:** September 28, 2026

## Overview

Version 1.2.1 adds support for OpenCode 2 alongside OpenCode 1.18, keeps WeChat routing aligned with the visible Codex session, and completes Claude Code model switches that require an extra confirmation. It also extends the validated Codex CLI range through 0.157 and restores executable permissions on the installed command launchers.

## OpenCode 2 Support

The bridge now supports the OpenCode 2 release line without dropping OpenCode 1.18. `wechat-opencode`, `wecom-opencode`, and daemon-managed OpenCode select the appropriate connection for the installed CLI version. Visible terminal sessions, remote model and plan controls, approvals and questions, session restoration, final replies, and prompts submitted in the local TUI remain connected to the channel. OpenCode 2 forwards locally submitted prompts; draft text is not mirrored because its TUI no longer emits the draft-update event. The weekly CLI compatibility check covers both supported release lines.

## Visible Session and Model Switching

- **Codex:** The validated CLI range now covers 0.149–0.157. When the visible Codex terminal opens a session in the bridge's startup workspace, WeChat follows that session instead of unrelated background activity. If the terminal opens a session from another workspace, WeChat receives a notice and stops sending input to the previous session until an in-workspace session is active again. Cross-workspace suspension and recovery have automated coverage but still require a live acceptance check.
- **Claude Code:** Selecting a model with `/model <number>` now handles the visible CLI's additional “Switch model?” confirmation, including the default-model choice, and verifies the resulting selection. Other or mismatched dialogs are not automatically confirmed.

## Launcher Reliability

Published `wechat-*`, `wecom-*`, and related command entrypoints retain executable permissions, so global installations can run their commands directly. The bridge continues to use standalone CLIs available on `PATH`, not binaries bundled inside desktop applications.

## Important Notes and Upgrade

The minimum Node.js version remains 22.13.0; the Pi adapter requires 22.19.0 or newer. No data migration or command change is required. Upgrade the primary package with:

```bash
npm install -g cli-wechat-bridge@latest
```

Existing scoped-package users can upgrade with:

```bash
npm install -g @unlinearity/cli-wechat-bridge@latest
```

Restart running bridge, daemon, and visible CLI processes after upgrading. Codex routing remains bound to the bridge's startup workspace; return the visible CLI to a session in that workspace to resume forwarding.
