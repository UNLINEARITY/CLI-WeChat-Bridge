# Version 1.1.1

**Release Date:** June 2, 2026

## Overview

Version 1.1.1 focuses on diagnostics and release-facing documentation. The built-in `--doctor` command now gives adapter-scoped checks with compact localized output, and the docs now explain the bridge architecture, PTY requirements, and common environment failures more clearly.

## Improvements

### Adapter-scoped doctor checks

- `wechat-daemon --doctor` now checks the daemon workflow across Codex, Claude Code, and OpenCode.
- Standalone commands such as `wechat-bridge-codex --doctor`, `wechat-bridge-claude --doctor`, and `wechat-bridge-opencode --doctor` now only check the selected adapter instead of listing every CLI.
- `wechat-bridge-shell --doctor` reports local shell usage without unnecessary Codex, Claude Code, or OpenCode command checks.
- Runtime diagnostics now cover daemon endpoints, bridge locks, workspace companion endpoints, stale endpoint files, credentials, data directories, Node.js, Windows build level, and `node-pty`.

### Compact localized output

- Doctor output is managed through the existing i18n catalog.
- Chinese remains the default language; set `CLI_BRIDGE_LANG=en` for English-only output.
- The command no longer prints bilingual Chinese/English lines together.
- Bridge-lock details are split into readable fields such as `pid`, `adapter`, `cwd`, `lifecycle`, `started at`, parent process status, and startup behavior.
- Row spacing was tightened so terminal output is easier to scan.

### Documentation and troubleshooting

- Added an architecture document covering the communication model for Codex, Claude Code, OpenCode, PTY usage, and adapter tradeoffs.
- Expanded PTY troubleshooting with platform prerequisites, fallback behavior, and `wechat-daemon --doctor` verification guidance.
- Updated the README navigation so users can find architecture and troubleshooting material from the project entry point.

## Upgrade Notes

Upgrade with:

```bash
npm install -g cli-wechat-bridge@latest
```

After upgrading, restart any running bridge, daemon, and companion terminals so they load the 1.1.1 runtime.

Existing scoped-package users can keep using:

```bash
npm install -g @unlinearity/cli-wechat-bridge@latest
```

## Compatibility

No data migration is required. The package still requires Node.js `>=24.0.0`, and the source/test workflow still uses Bun.
