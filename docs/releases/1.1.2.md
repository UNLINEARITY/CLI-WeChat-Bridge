# Version 1.1.2

**Release Date:** July 7, 2026

## Overview

Version 1.1.2 is a reliability and cross-platform install release. It stops the bridge from silently falling back to non-PTY mode on macOS and Linux because node-pty's spawn-helper binaries ship without an executable bit, hardens every adapter against crashes and turn-completion races, makes shared state writes atomic and inbound dedup fail-closed, restores Windows environment variables that an over-strict whitelist was dropping, rewrites update checks to query the npm registry so global installs no longer need a git repo, and adds a three-OS CI quality gate.

## Improvements

### Cross-platform install (node-pty)

- A `postinstall` script now restores the executable bit on node-pty's prebuilt spawn-helper binaries, which are published as `0644` (no exec bit). Without it, `posix_spawnp` failed on macOS and Linux and the bridge silently fell back to non-PTY mode — Claude even surfaced `Error: Input must be provided ... when using --print` while `--doctor` still reported node-pty as loaded, because the doctor check only verifies `require`, not an actual fork. The script is idempotent and never fails the install.
- The postinstall script itself is now listed in the published `files`, fixing `MODULE_NOT_FOUND` during `npm install -g`.

### Reliability and crash fixes

- OpenCode turn completion is now guarded by a monotonic turn token, so a stale deferred completion can no longer clobber a freshly started turn (flipping status back to idle, emitting the old `final_reply`, or clearing the new turn's buffered output).
- Codex app-server spawn failures no longer crash the bridge; the child process carries an error handler.
- Claude's invalid-resume recovery now catches failures and emits a `fatal_error` instead of leaving an unhandled rejection, and the Claude hook TCP line buffer is capped at 1 MiB.
- The PTY fallback path now surfaces spawn errors (`ENOENT`/`EACCES`) as an exit and swallows stdin broken-pipe after the child exits, and the detached background bridge spawn gained a matching error handler.
- POSIX process-tree termination now walks descendants via `pgrep` and kills leaves-first, so Codex/OpenCode grandchildren spawned without a detached process group are no longer re-parented to init on Linux and macOS.

### State persistence and inbound dedup

- Shared state (`context_tokens.json`, `bridge-state`, `bridge-lock`) is now written atomically via a temp file and rename, so a crash mid-write can no longer leave a truncated or half-written file that breaks the next launch or reads as a stale lock.
- The inbound message claim now fails closed on non-`EEXIST` filesystem errors (returns `false` instead of claiming ownership without writing the claim file), preventing concurrent processes from double-processing the same message. Claim cleanup deletes from a `readdir` snapshot instead of a recursive `rmdir` that could erase a claim a concurrent process just created.
- Bridge log growth is now bounded by a shared `appendBoundedLog` (5 MiB cap, trims to the tail half), and the update-check `setTimeout` is unref'd so it can no longer keep the event loop alive and race forced-exit teardown. `getUploadUrl` now wraps its `JSON.parse` so a 200-OK non-JSON response no longer throws an unclassified `SyntaxError`.

### Environment and message handling

- Windows no longer drops `ANTHROPIC_BASE_URL` and `OPENAI_API_KEY`: child processes now receive the full `process.env` instead of a too-strict whitelist.
- The WeChat message startup grace window grew from 5s to 30s to absorb clock skew, and messages without a timestamp are treated as fresh instead of discarded.
- Long replies are split into ~1200-character chunks with newline-aware breaks so final replies are no longer rejected by the WeChat server.
- Attachment absolute-path detection now uses a platform-independent regex that recognizes Windows drive paths (`C:\`, `C:/`), POSIX roots (`/`), and UNC paths, and no longer rewrites separators to `path.sep` — fixing silent attachment drops on Linux/macOS where a Windows drive path was rewritten and then rejected. This is what unblocked the attachment tests on non-Windows CI runners.
- Doctor diagnostics add WeChat server clock-skew detection, Windows code-page checks, and proxy environment variable inspection.
- A new `CLI_BRIDGE_STRICT_APPROVAL` mode disables all auto-approval and forces every permission request to WeChat.

### Update checks

- `wechat-check-update` now queries the npm registry (falling back to the GitHub tags API) instead of `git ls-remote --tags`, so it works for global installs that are not in a git repo.
- Every forced `process.exit()` was replaced with `process.exitCode` plus a natural return to fix a libuv `UV_HANDLE_CLOSING` assertion abort on Windows + Node 24, where a forced exit raced undici's handle teardown. Added `parseVersion` (v-prefix tolerant) and 16 tests.

### CI and contributor experience

- A GitHub Actions quality gate now runs lint + typecheck + test + build on pull requests and pushes to `main` across an Ubuntu/macOS/Windows matrix with `fail-fast` disabled, because node-pty's spawn-helper behavior is platform-specific. Bun install is cached, keyed on `bun.lock`.
- A bilingual pull-request template carries a short three-item self-check (full rules live in `CONTRIBUTING.md`), and the README gained a CI status badge.

## Upgrade Notes

Upgrade with:

```bash
npm install -g cli-wechat-bridge@latest
```

After upgrading, restart any running bridge, daemon, and companion terminals so they load the 1.1.2 runtime.

Existing scoped-package users can keep using:

```bash
npm install -g @unlinearity/cli-wechat-bridge@latest
```

## Compatibility

No data migration is required. The package still requires Node.js `>=24.0.0`, and the source/test workflow still uses Bun. The node-pty postinstall exec-bit fix now runs on every install (idempotent, never fails the install).
