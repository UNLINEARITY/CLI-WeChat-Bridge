# Version 1.0.6

**Release Date:** May 23, 2026

## Overview

Version 1.0.6 is a bridge approval and WeChat file-send reliability release. It makes Codex and Claude Code less noisy for ordinary read/search work, keeps genuinely risky operations visible for approval, and prevents all supported adapters from trying to stage outbound WeChat attachments in fake local bridge directories.

The release is focused on day-to-day WeChat control: asking an agent to find a file, locate an image, or inspect notes should no longer produce repeated local-terminal approval prompts. When a destructive command, broad permission grant, or risky file-system operation is requested, the bridge still keeps that decision explicit and routes it through the proper approval path.

## Approval Flow Fixes

### Codex approvals and follow-up questions

- Codex command, file-change, and permission approval requests are now handled by the bridge instead of staying in the local TUI.
- Low-risk Codex command and permission approvals are accepted automatically.
- High-risk Codex command and permission approvals are forwarded to WeChat with actionable approval state.
- Codex `request_user_input` prompts are forwarded to WeChat and can be answered with `/answer`.
- Pending user-input state now blocks deferred Codex message draining until the answer is submitted.
- For locally followed Codex threads, the bridge now attempts best-effort thread subscription before and after `turn/start`; `no rollout found` is treated as a soft failure so normal WeChat turns continue.

### Claude low-risk permissions

- Claude Code now auto-approves low-risk Bash commands used for reading, searching, and listing files.
- Read-only Claude tools such as `Read`, `LS`, `Glob`, `Grep`, `NotebookRead`, and `TodoRead` are auto-approved.
- Destructive commands still require approval.
- High-risk shell detection now covers plain `rm`, `find -delete`, `find -exec rm`, and `xargs rm` so deletion paths do not slip through the low-risk path.

## WeChat Attachment Sending Fixes

- The WeChat attachment prompt now tells adapters to reference the original absolute local file path in the final `wechat-attachments` block.
- The prompt explicitly forbids staging files under `.claude/channels/wechat`, `.cli-bridge`, or any `outbound-attachments` directory.
- Claude permission hooks now auto-deny `Write`-style tools and write-like Bash commands that target outbound attachment staging directories.
- Codex approval requests that target fake outbound attachment staging paths are auto-denied before any WeChat approval is emitted.
- OpenCode permission events that target fake outbound attachment staging paths are rejected through the SDK before becoming pending approvals.
- OpenCode now also checks lowercase `metadata.filepath`, `metadata.parentDir`, and `external_directory` permission variants.
- Claude multi-line WeChat prompts are submitted with bracketed paste and a delayed Enter so attachment instructions are sent as one prompt instead of getting stuck in the visible terminal.

## Documentation And Maintenance

- `AGENTS.md` now documents the daemon-first mental model, `~/.cli-bridge` runtime state, dual package publishing, release workflow, adapter behavior, and troubleshooting workflow in one place.
- The README license badge now uses npm package metadata for the primary package.

## Upgrade Notes

Upgrade with:

```bash
npm install -g cli-wechat-bridge@latest
```

After upgrading, restart any running bridge, daemon, and companion terminals so they load the 1.0.6 runtime.

Existing scoped-package users can keep using:

```bash
npm install -g @unlinearity/cli-wechat-bridge@latest
```

Both package names expose the same `wechat-*` commands. Install only one globally at a time.

## Compatibility

No CLI command removals or data migrations are introduced in this release. The package still requires Node.js `>=24.0.0`, and the test workflow still uses Bun.
