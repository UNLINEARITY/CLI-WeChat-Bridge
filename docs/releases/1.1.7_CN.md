# 版本 1.1.7

**发布日期：** 2026 年 9 月 1 日

## 概览

1.1.7 新增基于官方智能机器人 WebSocket SDK 的企业微信通道，并补齐企业微信的配置、配对、daemon、适配器和媒体处理入口。本版本同时加固 Claude Code 远程输入提交、Windows 进程身份检查和 Windows 微信二维码登录。README 现在使用由 GitHub Actions 生成的仓库自有静态 Star History 图片，不再依赖受限的托管 stargazer 接口。

## 企业微信智能机器人通道

包中新增 `@wecom/aibot-node-sdk@1.0.7` 以及 `wecom-setup`、`wecom-check-update`、`wecom-daemon`、`wecom-codex`、`wecom-claude`、`wecom-opencode` 和 `wecom-pi` 公共命令。`wecom-setup` 会通过官方 WebSocket 连接校验 Bot ID 和 Secret，显示一次性配对码；操作者在单聊中发送 `/pair <code>` 后，程序保存配对的操作者身份。

企业微信直接启动器和 daemon 复用微信通道的 adapter slot、命令语法、审批、会话恢复和本地 companion 流程。通道支持企业内部单聊和内部群聊、顺序文本回复与流式回复、入站图片/文件/视频下载解密以及出站文本和媒体发送。企业微信凭据、下载附件和入站去重状态隔离在 `~/.cli-bridge/wecom`；工作区锁和 adapter 状态保持共享，从而避免同一工作区同时被两个远程通道控制。

每个企业微信 Bot ID 同时只能保持一个有效 WebSocket 连接。外部群、客户群、回调应用和企业微信私有化部署不在当前支持范围内。官方 SDK 的大文件上传 ACK 延迟仍是已知限制；bridge 会顺序发送附件，并返回文件名和失败类型，不会静默丢弃传输。

## Claude Code 远程输入

Claude Code 现在会先等待交互式 `SessionStart` 信号，再把远程 prompt 写入 PTY。bridge 使用 bracketed paste 写入文本，在短暂延迟后发送 Enter；如果对应的 `UserPromptSubmit` hook 尚未到达，会在 200 毫秒、500 毫秒和 1 秒后重试 Enter。输入被接受、turn 完成、任务中断、session 重置或进程退出时都会取消重试；无效 resume 恢复也会先重建交互式 adapter，再继续尝试。

该修改修复了 Windows 路径下微信或企业微信消息停留在可见 Claude 输入框、没有真正提交的问题，同时保留本地键盘输入和基于 hook 的审批流程。

## Windows 进程检查与 CI

Windows bridge 所有权检查现在通过 `Win32_Process -Filter` 直接查询记录的 PID，不再枚举全部进程。命令行 bridge 过滤和 PID 复用保护保持不变，冷启动与 CI 检查不再执行此前的全量进程扫描。进程身份回归测试超时提高到 12 秒，CI matrix job 名现在包含操作系统和 Node.js 版本，六个检查可以明确区分。

## 微信二维码登录

`wechat-setup` 继续默认使用紧凑的 `small` 二维码，包括 Windows；对于压缩 Unicode 方块渲染异常的终端，可以使用 `--qr-mode normal`。登录现在要求交互式终端，并会根据终端宽度检查二维码是否适合显示；无法安全渲染时改为输出短期浏览器 URL。该 URL 只写入交互式终端，不进入运行时日志，也不会出现在非 TTY 输出中。

## 静态 Star History

仓库新增 `.github/workflows/star-history.yml`，按每日计划运行，也支持 `workflow_dispatch`，并申请 `contents: write`。工作流调用固定提交版本的 `narayann7/star-history-action`，写入固定路径 `assets/star-history/star-history.png`，再更新 README 标记块。README 不再依赖 `api.star-history.com`；工作流进入 GitHub 后需要先手动运行一次，才能生成图片文件。

## 文档与升级

README、通信架构、开发说明、运行配置、问题排查和发布索引现在同时描述微信与企业微信的入口、状态文件、限制、源码模式命令和通道差异。历史指令审计已明确标记为 1.1.5 时期的快照，避免被误认为当前命令清单。

Node.js 最低版本仍为 `22.13.0`。升级主包：

```bash
npm install -g cli-wechat-bridge@latest
```

已有 scoped 包用户可以升级：

```bash
npm install -g @unlinearity/cli-wechat-bridge@latest
```

升级后请重启正在运行的 bridge、daemon 和可见 CLI。修改企业微信 Bot 凭据或配对设置后，建议运行 `wecom-setup --check`。
