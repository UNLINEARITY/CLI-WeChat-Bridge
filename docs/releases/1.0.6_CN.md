# 版本 1.0.6

**发布日期：** 2026 年 5 月 23 日

## 概览

1.0.6 是一次面向桥接审批体验和微信文件发送可靠性的修复版本。它让 Codex 与 Claude Code 在普通读取、查找、列目录场景下不再频繁打断用户，同时保留真正高风险操作的明确审批，并阻止所有受支持 adapter 把微信出站附件错误地复制到本地假 staging 目录。

这个版本聚焦日常微信控制体验：让 agent 找文件、找图片、查看笔记时，不应反复弹出本地终端审批；当请求涉及删除、广泛授权或高风险文件系统操作时，bridge 仍会把决策保留在审批路径中。

## 审批流程修复

### Codex 审批与追问

- Codex 命令、文件变更和权限审批请求现在会进入 bridge 处理，不再只停留在本地 TUI。
- 低风险 Codex 命令和权限审批会自动通过。
- 高风险 Codex 命令和权限审批会转发到微信，并保留可操作的审批状态。
- Codex `request_user_input` 会转发到微信，并可通过 `/answer` 回答。
- 等待用户补充输入时，deferred Codex 消息队列不会提前 drain。
- 对本地 follow 的 Codex thread，bridge 会在 `turn/start` 前后尽力订阅；`no rollout found` 被视为软失败，普通微信回合不会因此中断。

### Claude 低风险权限

- Claude Code 现在会自动通过用于读取、搜索和列目录的低风险 Bash 命令。
- `Read`、`LS`、`Glob`、`Grep`、`NotebookRead`、`TodoRead` 等只读 Claude 工具会自动通过。
- 删除等破坏性命令仍需要审批。
- 高风险 shell 检测补充了普通 `rm`、`find -delete`、`find -exec rm` 和 `xargs rm`，避免删除路径被低风险策略误放行。

## 微信附件发送修复

- 微信附件提示词现在明确要求 adapter 在最终 `wechat-attachments` 块里引用原始本地绝对路径。
- 提示词明确禁止把文件 staging 到 `.claude/channels/wechat`、`.cli-bridge` 或任何 `outbound-attachments` 目录。
- Claude permission hook 现在会自动拒绝指向 outbound attachment staging 目录的 `Write` 类工具和写入型 Bash 命令。
- Codex 命中假 outbound attachment staging 路径的审批请求会在生成微信审批前自动拒绝。
- OpenCode 命中假 outbound attachment staging 路径的 permission event 会通过 SDK 直接 reject，不再进入 pending approval。
- OpenCode 现在也会检查小写 `metadata.filepath`、`metadata.parentDir` 和 `external_directory` 权限变体。
- Claude 多行微信 prompt 现在使用 bracketed paste 和延迟 Enter 提交，确保附件提示作为完整 prompt 发出，而不是卡在可见终端里。

## 升级说明

使用以下命令升级：

```bash
npm install -g cli-wechat-bridge@latest
```

升级后，请重启正在运行的 bridge、daemon 和 companion 终端，让它们加载 1.0.6 运行时。

已经使用 scoped 包名的老用户也可以继续使用：

```bash
npm install -g @unlinearity/cli-wechat-bridge@latest
```

两个包名导出的都是同一组 `wechat-*` 命令。全局环境中只需要安装其中一个。

## 兼容性

本版本没有移除 CLI 命令，也没有新增数据迁移。包仍要求 Node.js `>=24.0.0`，测试工作流仍使用 Bun。
