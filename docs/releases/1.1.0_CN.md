# 版本 1.1.0

**发布日期：** 2026 年 5 月 27 日

## 概览

1.1.0 引入国际化（i18n）系统，默认语言改为中文；新增 Claude 思考过程实时转发到微信；修复 Claude 自动批准响应丢失的严重 bug；以及多项可靠性改进，包括 Codex 进程树清理和跨平台桥接诊断。

## 新功能

### 国际化（i18n）

- 轻量级 i18n 系统，无第三方依赖。
- 中文为默认语言，所有用户可见消息默认中文显示。
- 通过 `CLI_BRIDGE_LANG=en` 环境变量切换为英文。
- `t(key, params?)` 查找函数，支持 `{param}` 插值。
- 覆盖范围：桥接/daemon 欢迎消息、hook 健康检查警告、PTY fallback 警告、spawn 诊断信息、emoji binding 管理消息。
- 当前语言缺少 key 时自动 fallback 到英文目录。

### Claude 思考过程转发

- 实时将 Claude 的思考过程转发到微信。
- 以 800ms 间隔轮询 Claude transcript 文件（JSONL），提取 thinking 块。
- 思考内容以"思考:"前缀转发。
- 默认关闭；通过 `CLI_BRIDGE_THINKING_FORWARD=1` 环境变量或 account.json 中 `enableThinkingForward: true` 开启。
- 用户输入/SessionStart 时启动 watcher，turn 结束时停止。

### 批量审批命令

- 队列架构替代单值审批存储，支持多个并发权限请求。
- 多个同时到达的权限请求进入队列而非互相覆盖。
- `/confirm`、`/yes`、bare "confirm"/"yes" 一次批量确认所有待审批。
- `/deny`、`/no`、bare "deny"/"no" 一次批量拒绝所有待审批。
- Bare text 审批命令现在对所有 adapter 类型生效（之前仅限 Claude）。

### 单桥模式 Emoji 绑定

- `/bind`、`/unbind`、`/bindings` 命令现在在独立单桥模式下也可使用（之前仅 daemon 模式）。
- 启动时显示欢迎消息，列出可用命令和当前绑定。
- 格式错误的 `/bind` 或 `/unbind` 命令返回用法提示，而非静默转发给 adapter。

## Bug 修复

### Claude 自动批准响应丢失（严重）

- 修复：非 Bash 工具（WebFetch、Read、Write 等）自动批准后，TCP 响应未到达 Claude Code，导致 Claude 卡在终端权限提示，微信无任何通知。
- 根因：Claude hook 使用一次性 TCP 连接，socket 关闭后响应丢失。
- 修复方案：保存最后一次自动批准的 payload，当收到 `permission_prompt` Notification 但无 pendingApproval 时，回退到将审批请求转发给微信用户手动批准。

### 扩展自动批准策略

- 所有非 Bash 工具权限（WebFetch、Read、Write、Glob、Grep 等）现在全部自动批准，不再仅限硬编码子集。

### Windows 上 Codex 进程树未被杀死

- `child.kill()` 只发信号给主进程，Codex app-server 的子进程在 daemon 退出后继续存活。
- 替换为 `killProcessTreeSync()`，Windows 上使用 `taskkill /T /F /PID`，Unix 上使用 `process.kill(-pid)`。

### 跨平台桥接失败诊断

- Hook 脚本 stderr 重定向到日志文件而非 /dev/null。
- 15 秒 hook 健康检查 timer，无 hook 事件到达时向微信发出诊断警告。
- node-pty 失败时自动 fallback 到 `child_process.spawn`，附带平台相关诊断信息。

## 升级说明

使用以下命令升级：

```bash
npm install -g cli-wechat-bridge@latest
```

升级后，请重启正在运行的 bridge、daemon 和 companion 终端，让它们加载 1.1.0 runtime。

已经使用 scoped 包名的老用户也可以继续使用：

```bash
npm install -g @unlinearity/cli-wechat-bridge@latest
```

## 兼容性

本版本不需要新的数据迁移。包仍要求 Node.js `>=24.0.0`，源码和测试工作流仍使用 Bun。
