# 版本 1.5.0

**发布日期：** 2026 年 11 月 17 日

## 概述

1.5.0 新增 CLI 协作功能。同一 daemon 管理的 CLI 可以相互委派任务，例如由 Codex 请求 Claude Code 审查代码，或启动独立工作会话处理另一项任务。任务状态、执行结果和审批请求会同步到微信、企业微信或 Telegram，方便你查看并参与处理。

本版同时提供默认窗口固定功能：`/pin` 可将普通消息持续发送到指定窗口，`/2 内容` 等带有明确目标的命令仍按原有方式工作。窗口关闭后，桥接模式会根据剩余窗口自动调整，解决退出其他 CLI 后仍无法使用 `/open` 的问题。

## CLI 协作与任务委派

### 任务委派与结果回传

任务以后台方式执行。接收任务的 CLI 忙碌时，新任务会进入队列；发起方可以继续工作，执行结果会在任务完成后作为新一轮消息返回。如果发起方已主动读取结果，系统不会重复发送。任务往来和待处理的审批、问题会同步到操作者的聊天通道。

新增的 `cli-bridge` MCP 服务提供以下 8 个工具：

| 工具 | 用途 |
| --- | --- |
| `list_agents` | 查看 daemon 管理的 CLI 窗口和 worker，以及各自的工作目录与运行状态 |
| `send_to_agent` | 向指定 CLI 委派任务，并获取调用 ID |
| `get_agent_call` | 查询任务状态和结果，或等待任务完成、审批请求或问题提示 |
| `interrupt_agent_call` | 取消排队中的任务，或中断正在执行的任务 |
| `open_agent` | 启动使用全新上下文的独立工作会话（worker） |
| `close_agent` | 关闭自己打开的 worker |
| `new_agent_session` | 在自己拥有的空闲 worker 中新建会话 |
| `resolve_agent_approval` | 按任务审批规则处理自己委派的任务所产生的权限请求 |

### 自动工具配置

- 通过桥接启动的 Claude Code 会自动配置这些工具。
- Codex 使用桥接启动并管理的 app-server 时，也会自动配置这些工具。
- 通过 `$codex-bridge` 接入已有 Codex 会话时，不会自动更改该会话的 MCP 配置。
- OpenCode 和 Pi 可以接收 daemon 转交的任务，目前不会自动配置用于发起调用的 MCP 工具。

如需自行配置 MCP 客户端，可使用安装包提供的 `cli-bridge-mcp` 命令，通过标准输入输出（stdio）连接服务；使用前需先启动 daemon。设置 `CLI_BRIDGE_AGENT_BUS=0` 可在启动 CLI 时关闭上述自动配置。

### 独立工作会话（worker）

worker 为独立任务提供全新的会话上下文，不会改变你已打开窗口的桥接模式或当前活动窗口。Codex worker 默认在后台运行，也可以要求打开可见窗口；其他 CLI 的 worker 使用可见终端窗口。

每个发起方最多同时保留 4 个 worker。只有创建它们的 CLI 可以关闭 worker 或重置其会话；该 CLI 退出时，所属 worker 也会关闭。已有会话保持不变。

### 任务审批

默认情况下，使用这些协作工具无需额外确认 MCP 调用，任务接收方的 CLI 权限设置仍然生效。设置 `CLI_BRIDGE_STRICT_APPROVAL=1` 后，协作工具调用也会遵循 CLI 的审批设置，同时在启动时关闭桥接的自动放行策略。

发起方只能批准符合统一自动放行规则的请求；接收方提出的高风险权限请求必须由操作者确认。对于这些请求，发起方仍可在 CLI 支持时选择拒绝，或拒绝并中止任务。Pi 的审批请求均由操作者处理。操作者与发起方同时作出决定时，以先到达的有效决定为准。

## 固定默认窗口

使用 `/pin` 后，未指定目标的消息和控制命令会持续发送到固定窗口，本地切换窗口不会改变这一默认目标。需要临时操作其他会话时，仍可使用 `/2 内容` 等命令明确指定目标。

| 命令或消息 | 行为 |
| --- | --- |
| `/pin` | 将当前窗口设为默认目标；已有有效固定目标时，重复执行保持原目标 |
| 普通文本或未指定目标的 `/stop` 等控制命令 | 使用固定窗口 |
| `/2 内容`、`/codex 内容` 或已绑定的表情命令 | 将本条消息发送到指定目标，固定窗口保持不变 |
| `/1`、`/2`、`/cd`、`/open`、`/all` | 保留原有的切换、新开窗口和广播行为 |
| `/unpin` | 恢复跟随活动窗口 |

每个桥接最多固定一个窗口，固定状态在主动取消、窗口关闭或 daemon 重启后失效。固定窗口关闭后，下一条未指定目标的消息不会被转发，桥接会清除固定状态并提示你重新选择窗口、发送消息。即使新窗口使用了相同编号，也不会继承原有固定状态。

Codex `/resume` 也会按目标窗口的工作目录和实例执行，避免在固定窗口或使用编号命令时恢复到其他会话。

## 桥接模式自动调整

窗口关闭后，桥接会根据剩余窗口重新确定模式：

- 只剩一个窗口时回到单桥接，回复不再带来源前缀，`/open` 可以再开一个窗口。
- 同一目录中，同一种 CLI 的多个窗口使用同类型多实例模式，通过编号区分。
- 同一目录中，不同 CLI 类型各有一个窗口时使用多 CLI 模式。
- 仍有多个工作目录时，继续使用多目录模式。若只剩一个目录，但其中既有不同类型的 CLI，又有同类型的多个实例，则保留完整的目录、CLI 和编号命令，直到剩余窗口适合切换为上述模式。

调整模式不会改变已有窗口的编号。当前活动窗口关闭时，桥接会自动选中一个剩余窗口。从聊天通道打开的可见窗口也会在关闭后移除对应的桥接实例，常驻 daemon 继续运行。通过附加模式接入的已有 Codex 会话仍按其原有生命周期运行。

## 兼容性与升级

Codex 的兼容性以桥接所需的协议能力检查为准，不再按固定版本区间限定。接入已有 Codex 会话仍需要 0.162 或更高版本提供的共享 daemon。Node.js 要求保持为 `>=22.13.0`；使用 Pi 时需要 `>=22.19.0`。

三个包名提供相同的版本和命令，以下安装命令选择一条执行即可：

```bash
npm install -g cli-chat-bridge@1.5.0
# 或继续使用以下任一已有包名：
npm install -g cli-wechat-bridge@1.5.0
npm install -g @unlinearity/cli-wechat-bridge@1.5.0
```

切换包名时，请先卸载当前安装的包，避免命令冲突。升级后需停止并重新启动 daemon 及其 CLI 窗口，才能加载新代码和 MCP 配置。凭据与已保存的会话无需迁移；窗口固定状态、待处理的协作任务及 worker 的归属关系不会在 daemon 重启后恢复。
