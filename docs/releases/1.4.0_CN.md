# 1.4.0 版本说明

**发布日期：** 2026 年 10 月 21 日

## 概览

1.4.0 改变了在微信、企业微信和 Telegram 中处理审批与问题的方式。

- **Codex、Claude Code、OpenCode 使用同一套自动审批规则。** 项目内的常规操作直接执行；破坏性命令、对本机以外产生影响的操作、写入工作区之外以及 MCP 工具调用，会发给你确认。
- **自动放行会告知你。** 回复中会说明本轮自动放行了哪些操作；`/auto on|off` 可在 daemon 运行期间切换规则。
- **更多审批回复。** `/always` 在本会话剩余时间内允许同类请求，`/deny <理由>` 把原因告诉模型，`/abort` 拒绝并停止本轮。
- **直接回复即可回答问题。** CLI 等待回答时，不以 `/` 开头的消息就是答案；多个问题逐个提问。

本版还修复了五个问题：桥接会替换你自己的 Codex 审批与沙箱设置；桥接会抢先回答本应由本地终端处理的 Codex 请求；在终端里处理过的 Claude Code 审批仍留在聊天中；微信"对方正在输入"有时在回复后仍显示；Codex 会话历史较大时 daemon 会停顿数百毫秒。

## 审批

### 三个 CLI 共用一套规则

1.4.0 之前各 CLI 规则不同：Codex 自动批准高风险列表以外的所有命令和所有文件修改；Claude Code 除高风险 shell 命令外全部放行，包括 MCP 工具和写入任意位置；OpenCode 从不自动批准。现在三者遵循同一套规则。

**发给你确认：**

| 类别 | 示例 |
| --- | --- |
| 破坏性本地命令 | `rm`、`sudo`、`dd`、`git reset --hard`、`git clean -f`、`git checkout -f`、`git restore`、`git branch -D`、`git stash drop`、`chmod -R`、`kill -9`、`pkill`、`curl … \| sh` |
| 对本机以外产生影响的命令 | `git push`；用 `npm`、`pnpm`、`yarn`、`bun`、`cargo`、`gem` 发布；`twine upload`；`docker push`、`docker login`；`gh release`、`gh pr create`/`merge`/`close`、修改 `gh repo`、`gh workflow run`；`deploy`、`vercel --prod`；`kubectl apply`/`delete`；`terraform apply`/`destroy`；`pulumi up`；`helm install`/`upgrade`；`aws s3` 写入；`ssh`、`scp`、`sftp`，以及向远程主机 `rsync` |
| 写入工作区之外 | 命令写入或重定向到项目目录之外的路径；在项目之外修改文件或授予权限 |
| 访问工作区之外 | OpenCode 请求使用项目之外的目录 |
| MCP 工具 | 所有 MCP 工具调用 |
| 只能由你决定的事 | 批准 Claude Code 的计划 |
| 桥接无法归类的请求 | 无法识别的权限类型，以及没有显示命令内容的命令 |

**自动放行：** 其余全部，包括读取、普通网络访问和工作区内的文件修改。Codex 在批准前不会说明修改涉及哪些文件，因此只有当 Codex 把修改范围限定在工作区内时，才会自动放行。

这套规则只作用于 CLI 发来审批的请求。如果 CLI 被配置为无需审批，它的操作不会经过桥接。

### 自动放行会告知你

本轮有请求被自动放行时，最终回复会在附件之前加一行，例如：

```text
本轮自动放行：2 条命令、1 个文件修改
```

计数按命令、文件修改、权限申请、联网、读取和其他操作分类，每轮重新计算。

### `/auto`

| 命令 | 作用 |
| --- | --- |
| `/auto` | 查看自动放行是否开启 |
| `/auto on` | 为所有窗口开启自动放行 |
| `/auto off` | 所有审批请求都发给你 |

设置持续到 daemon 退出。daemon 启动时默认开启自动放行，除非启动时设置了 `CLI_BRIDGE_STRICT_APPROVAL=1`。

### 审批回复

| 回复 | 作用 | 适用范围 |
| --- | --- | --- |
| `/confirm`、`/yes`、`confirm`、`yes` | 允许这一请求 | 所有 CLI |
| `/always` | 允许这一请求，本会话剩余时间内同类请求不再询问；不修改你的设置文件 | Codex：请求支持会话内批准时；Claude Code：它给出权限规则建议时 |
| `/deny`、`/no`、`deny`、`no` | 拒绝这一请求 | 所有 CLI |
| `/deny <理由>` | 拒绝并把理由告诉模型 | Claude Code 与 OpenCode 随拒绝一起收到理由；Codex 在本轮结束后以下一条消息收到 |
| `/abort` | 拒绝并停止当前这一轮 | Claude Code 与 OpenCode；Codex：请求允许取消时 |

每条审批消息只列出该请求可用的回复，并说明后面还有几个请求在等待。请求不支持的回复会被拒绝并附提示，例如改为先发 `/deny` 再发 `/stop`。OpenCode 自带的"始终允许"会保存为永久的项目规则，因此 OpenCode 不提供 `/always`。

## 问题

Claude Code、Codex 或 OpenCode 向你提问时：

- **不以 `/` 开头的消息就是答案。** 以前普通消息会被拦下，必须使用 `/answer`；`/answer` 仍然可用。
- **用编号或完整的选项名称选择。** 多选时用逗号（`,` 或 `，`）、`、` 或空格分隔，例如 `1 3`。
- **为选项附加说明**：在编号后接文字，例如 `2 先别部署`。
- **填写自己的答案**：发送其他任何文字即可；如果问题只允许从选项中选择，会请你重新选择。
- **多个问题逐个提问**，每题标明序号，例如 `问题 1/3`，最后一题回答后一起提交。也可以一次答完：`问题编号=答案; 问题编号=答案`。

桥接不会替你回答，也不会预选选项。三个 CLI 的规则一致；以前 Codex 要求在 `|` 之后写说明，多选只接受 `,`。

## 问题修复

### Codex 保留你的审批与沙箱设置

由桥接自己启动 Codex 时，桥接会在每个新线程、恢复的线程和每一轮中，把审批策略设为"按需询问"、审批人设为你、沙箱设为"可写工作区"。这会替换"从不询问""完全访问""自动审查"等设置，还可能改变与终端共享的线程的设置。现在桥接不再设置这些项：新线程使用你的 Codex 配置，恢复的线程保留自身设置。如果你的 Codex 配置为完全访问，远程任务不会再发来审批请求。

### 本应由终端处理的 Codex 请求

Codex 会把每个请求发给连接到同一线程的所有窗口，并采用最先到达的回答。桥接以前会立即回答全部请求，导致即使你就在终端前，MCP 工具调用也会被拒绝。现在：

- MCP 工具审批像其他审批一样发给你，用 `/confirm` 或 `/deny` 回答。
- MCP 服务器请你填写的表单、打开的链接和设备验证留给终端处理，聊天中会提示你到终端完成。
- 其他线程的请求，以及桥接不处理的请求类型，都留给终端。

### 在终端处理过的 Claude Code 审批

在 Claude Code 自己的终端对话框中处理过的审批，会一直留在聊天中，并拦住普通消息直到本轮结束。现在工具执行、执行失败或提交新提示词时，审批会立即关闭。如果 `/confirm` 在审批消息送达之前到达，桥接不再批准你没看到的请求，而是先把当前请求发给你。

### 微信"对方正在输入"

如果一轮在"正在输入"状态尚未开启完成时就结束了，这个状态可能在回复后一直显示。现在这个状态：

- 只有为该联系人开启它的所有窗口都结束后才关闭；
- 等待你审批或回答问题时暂停，你回复后恢复；
- 发送 `/abort` 时关闭；CLI 进入空闲、停止或报错时也会关闭。

### Codex 会话历史较大时的停顿

为了找到当前的 Codex 会话，桥接会把 `~/.codex/sessions` 中的每个文件完整读一遍，而实际只需要第一行；在等待新会话出现期间，最多每秒重复两次。每次扫描期间 daemon 无法处理消息。67 个会话文件、共 1.4 GB 时，一次扫描耗时 280–680 毫秒；现在每个文件只读第一行，耗时 3–12 毫秒。

## 升级与兼容说明

### 安装

新用户请安装更短的 `cli-chat-bridge`（项目即将使用的新名称）：

```bash
npm install -g cli-chat-bridge@1.4.0
```

内容完全相同的 `cli-wechat-bridge` 并列发布：

```bash
npm install -g cli-wechat-bridge@1.4.0
```

`@unlinearity/cli-wechat-bridge` 继续同步发布，供已安装的用户正常升级：

```bash
npm install -g @unlinearity/cli-wechat-bridge@1.4.0
```

三个包提供相同的命令，只需安装其中一个。要切换包名，请先卸载当前的包，例如 `npm uninstall -g @unlinearity/cli-wechat-bridge`，否则 npm 会因 `EEXIST` 中止安装。

### 重启

停止正在运行的 daemon 和可见 CLI 窗口，然后重新启动。升级前启动的 Claude Code 与 OpenCode 窗口在重启之前只接受 `/confirm` 和 `/deny`，不跟随 `/auto`，也不会传递 `/deny` 的理由。凭据和已保存的状态无需迁移。

### 行为变化

- **OpenCode 开始自动放行常规请求。** 以前每个请求都发给你。要保持原来的行为，发送 `/auto off`，或用 `CLI_BRIDGE_STRICT_APPROVAL=1` 启动 daemon。
- **Claude Code 询问得更多。** MCP 工具、写入工作区之外、批准计划，以及对本机以外产生影响的命令，现在都需要你确认。
- **Codex 按你自己的配置执行。** Codex 配置为完全访问或从不询问时，远程任务不再因审批而停下。
- **普通消息会回答等待中的问题**，不再被拦下。问题等待期间要发送命令，请以 `/` 开头。

### 运行要求

- Node.js `>=22.13.0`；Pi 要求 `>=22.19.0`。
- Codex：常规桥接支持 0.149.x–0.161.x；附加到正在运行的会话需要 Codex 0.162 或更高版本。
- Codex MCP 的表单、链接和设备验证需要在终端中完成。
