# 版本 1.1.1

**发布日期：** 2026 年 6 月 2 日

## 概览

1.1.1 聚焦诊断能力和发布面向的文档。内置 `--doctor` 命令现在提供按适配器收敛的检查和更紧凑的本地化输出，文档也补充了桥接架构、PTY 依赖和常见环境故障排查说明。

## 改进

### 按适配器收敛的 doctor 检查

- `wechat-daemon --doctor` 现在面向 daemon 工作流，检查 Codex、Claude Code 和 OpenCode。
- `wechat-bridge-codex --doctor`、`wechat-bridge-claude --doctor`、`wechat-bridge-opencode --doctor` 等独立桥接命令现在只检查选中的适配器，不再列出所有 CLI。
- `wechat-bridge-shell --doctor` 会报告本地 shell 使用方式，不再显示不相关的 Codex、Claude Code 或 OpenCode 命令检查。
- 运行时诊断覆盖 daemon endpoint、bridge lock、工作区 companion endpoint、过期 endpoint 文件、凭据、数据目录、Node.js、Windows build 版本和 `node-pty`。

### 紧凑的本地化输出

- Doctor 输出统一由现有 i18n 目录管理。
- 中文保持默认语言；设置 `CLI_BRIDGE_LANG=en` 后切换为纯英文输出。
- 命令不再把中文和英文双语内容同时打印在同一份输出里。
- Bridge lock 详情拆成更易读的字段，例如 `pid`、`适配器`、`目录`、`生命周期`、`启动时间`、父进程状态和启动行为。
- 行距和对齐方式改为更紧凑的终端格式，便于快速扫描。

### 文档与排障

- 新增架构文档，说明 Codex、Claude Code、OpenCode 的通信模型、PTY 使用方式和适配器取舍。
- 扩展 PTY 排障说明，补充平台前置条件、fallback 行为和 `wechat-daemon --doctor` 验证方式。
- 更新 README 文档导航，让用户可以从项目入口直接找到架构和排障材料。

## 升级说明

使用以下命令升级：

```bash
npm install -g cli-wechat-bridge@latest
```

升级后，请重启正在运行的 bridge、daemon 和 companion 终端，让它们加载 1.1.1 runtime。

已经使用 scoped 包名的老用户也可以继续使用：

```bash
npm install -g @unlinearity/cli-wechat-bridge@latest
```

## 兼容性

本版本不需要新的数据迁移。包仍要求 Node.js `>=24.0.0`，源码和测试工作流仍使用 Bun。
