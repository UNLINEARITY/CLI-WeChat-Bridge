# Version 1.2.3

**Release Date:** October 13, 2026

## Overview

Version 1.2.3 adds Telegram as a third messaging channel and lets you attach a channel to an already running Codex TUI conversation. It fixes missing Telegram final replies in standalone and attach mode, makes launch messages identify the actual channel, and provides complete Chinese and English READMEs with language navigation.

## New Features

### Telegram Bot API Channel

Telegram supports Codex, Claude Code, OpenCode, and Pi through the same direct-launch and daemon workflows as WeChat and WeCom. It uses official Bot API long polling and needs no public callback URL.

1. Create a bot with `@BotFather` using `/newbot` and obtain its Bot Token.
2. Run `telegram-setup` locally and enter the token.
3. Open a private chat with the bot, click Start, and send the terminal's `/pair <code>` within 10 minutes.
4. Enter your project directory and start `telegram-daemon --adapter codex`, or use a direct launcher.

| Purpose | Command |
| --- | --- |
| Pair an operator | `telegram-setup` |
| Check saved credentials | `telegram-setup --check` |
| Persistent daemon | `telegram-daemon` |
| Direct launchers | `telegram-codex`, `telegram-claude`, `telegram-opencode`, `telegram-pi` |
| Check package updates | `telegram-check-update` |

- Messages from the paired operator drive the active local session. Daemon commands such as `/codex`, `/claude`, `/opencode`, and `/pi`, together with shared controls for status, models, approvals, and questions, use the existing command grammar.
- Text replies, final replies, and attachments return through Telegram. Long text is split to fit message limits, and tasks show Telegram's native typing indicator.
- Incoming images, files, videos, voice messages, and audio are downloaded locally and added to the CLI prompt as paths. The bridge does not perform OCR or document extraction.
- Credentials are saved in `~/.cli-bridge/telegram/account.json`; attachment and deduplication state also use the Telegram subdirectory. `CLI_BRIDGE_DATA_DIR` changes the common data root.
- `TELEGRAM_BOT_TOKEN`, `TELEGRAM_OPERATOR_USER_ID`, `TELEGRAM_OPERATOR_CHAT_ID`, and the optional `TELEGRAM_BOT_USERNAME` can override saved configuration. Token rejection and concurrent-poller conflicts are distinguished in transport errors.

### Attach the Current Codex Conversation

With Codex >= 0.162 running through its shared app-server daemon, attach a messaging channel to the existing live conversation:

```bash
wechat-codex --attach-current-session
wecom-codex --attach-current-session
telegram-codex --attach-current-session
```

Run the command in the conversation's project directory or pass `--cwd <path>`. The bridge discovers the newest live root thread in that directory; use `--codex-thread-id <id>` to select a specific thread when several are active.

- Chat messages become turns in the same Codex thread, and replies and approvals return to the channel. The owning TUI and its conversation context stay in place.
- Attach mode joins the shared daemon as a guest client and inherits the thread's approval and sandbox settings without overriding them.
- The background bridge survives launcher exit, reconnects and rejoins after unexpected disconnections, and supports the existing `/resume` path.
- Success is reported only when the saved thread matches the active bridge instance, working directory, channel, and explicitly requested thread. Old bridge session state cannot stand in for a fresh attachment.

The `codex-bridge` skill is included in both npm packages. Install it from the primary package with:

```bash
node "$(npm root -g)/cli-wechat-bridge/skills/codex-bridge/scripts/install.mjs"
```

Then invoke `$codex-bridge` in the Codex TUI and name the desired channel. See the [connection guide](../codex-connection.md#english) for requirements and errors.

## Fixes and Improvements

- **Telegram final replies:** Standalone and attach bridges now use `TelegramChannelPort` for final text and attachments. Previously, these replies fell into the WeChat port and failed with `WeChat channel cannot send to telegram`, while daemon replies and ordinary notices could still work.
- **Reply targets:** Regression coverage verifies that asynchronous Telegram final text and attachments retain the conversation captured when the event arrived, even if the active target changes before sending.
- **Channel-aware startup:** Launch, replacement, daemon delegation, help, attach confirmations, and argument-error messages identify the selected channel. Shared channel names and complete port/credential registrations prevent new channels from silently falling back to WeChat.
- **Documentation:** The README covers Telegram setup and controls across all three channels. A full English README adds reciprocal language links, translated titles and image descriptions, and an English product-site entry. Screenshots use centered HTML references at 85% width, and the product-site badge uses a simple globe icon.
- **Release packaging:** Both packages include the English README and Codex bridge skill. Package-lock command metadata includes all 21 public entry points, and global smoke checks cover all 15 noninteractive daemon/adapter launchers across the three channels.

## Upgrade and Compatibility Notes

### Install and Restart

```bash
npm install -g cli-wechat-bridge@1.2.3
```

Existing users of the scoped compatibility package can continue with:

```bash
npm install -g @unlinearity/cli-wechat-bridge@1.2.3
```

Restart active bridges, daemons, and visible CLI clients to load the new code. For an attached Codex conversation, rerun the attach command from the same project directory to replace the old bridge and keep using the same TUI thread. Existing WeChat and WeCom credentials need no migration.

### Operating Limits

- Node.js remains `>=22.13.0`; Pi requires `>=22.19.0`. The established Codex compatibility range remains 0.149.x–0.161.x; the new shared-daemon attach workflow requires Codex >=0.162 and was verified locally with 0.162.1.
- Attach requires the shared daemon control socket and a live session in the requested directory. Desktop-app embedded sessions and sessions started with `--no-daemon`, `--oss`, or an embedded profile cannot be attached.
- A running channel daemon holds the workspace bridge lock and blocks attach. Use its slots, or stop it before attaching. Plain `telegram-codex` opens a bridge-managed visible CLI; add `--attach-current-session` to attach an existing conversation.
- Run one Telegram polling process per Bot Token, including during pairing. A previously configured webhook must be removed before using long polling. Pair in a private chat and use the paired operator account for subsequent input.
- No existing public launcher is removed in this release. Channel credentials remain separate, while workspace locks and daemon endpoints remain shared.
