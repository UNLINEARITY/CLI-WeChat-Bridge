# 版本 1.0.9

**发布日期：** 2026 年 5 月 26 日

## 概览

1.0.9 新增微信表情绑定功能，用户可以通过发送微信表情快速触发 daemon 命令。同时包含多项运行时 bug 修复：进程生命周期、资源安全、Claude hook 覆盖范围、macOS 和 Linux 上的可见终端支持，以及协议从 MIT 变更为 AGPL-3.0 + 商业双协议。

## 新功能：表情绑定

### 默认绑定

开箱即用提供六个默认表情到命令的映射：

| 表情 | 命令 | 说明 |
|------|------|------|
| `[OK]` | `/confirm` | 批准权限请求 |
| `[闭嘴]` | `/stop` | 中断当前任务 |
| `[拥抱]` | `/claude` | 切换到 Claude Code |
| `[强]` | `/codex` | 切换到 Codex |
| `[胜利]` | `/opencode` | 切换到 OpenCode |
| `[再见]` | `/daemon-stop` | 停止 daemon |

### 管理命令

用户可以直接在微信中管理绑定：

- `/bindings` — 查看当前所有绑定
- `/bind [表情] /命令` — 绑定表情到命令
- `/unbind [表情]` — 解除绑定

### 行为规则

- 表情必须出现在消息开头才会触发（前缀匹配）。
- 当表情解析为切换命令且后面有文本时（如 `[拥抱]帮我写个脚本`），先切换 adapter，再将剩余文本作为消息转发给新 adapter。
- 大小写不敏感（`[OK]` 和 `[ok]` 等价）。
- 绑定持久化到 `~/.cli-bridge/emoji-bindings.json`，daemon 重启后保留。
- 运行时匹配零 IO：配置在 daemon 启动时加载到内存 Map，修改时同步更新 Map、异步写入文件。

## Bug 修复

### Stop 后无法恢复

- Claude adapter 的 `interrupt()` 现在调用 `scheduleTaskComplete()` 并设置 1.5s 回退超时，防止 Stop hook 未触发时 adapter 永久卡在 "busy" 状态。

### 微信图片无法读取

- 入站附件提示改为强制性 ACTION REQUIRED 语言，迫使 Claude 在回复前 Read 图片文件。

### Daemon 接管丢失会话

- Daemon 启动时捕获 `cleanupSingleBridgeBeforeDaemon()` 的返回值，对刚被杀掉的同一 adapter 使用 `session_start_mode=restore`，保留被中断的对话。

### 进程生命周期与资源安全

- POSIX 进程树终止通过负 PID 杀死整个进程组。
- PTY dispose 等待进程退出（3s 超时）防止竞态。
- Daemon 信号处理器使用防重入守卫，第二信号强制退出。
- Windows 清理直接使用 `taskkill` 而非无效的 SIGTERM。
- Companion 和 Codex RPC 请求添加 30s 超时。
- Socket 断开时 reject 孤立的 pending requests。
- IPC 缓冲区限制 1MB 防止 DoS。
- 会话日志轮询改为增量读取。
- 不安全的 `proc.pid!` 断言替换为 null 守卫。

### Claude hook 覆盖

- Hook 事件覆盖从 6 个扩展到 11 个（新增 PreToolUse、PostToolUse、PreCompact、PostCompact、SubagentStop）。
- PostCompact 作为可靠的 compact 完成信号。

## macOS 和 Linux 可见终端

- macOS：使用 `osascript` 打开 Terminal.app 运行 companion 命令。
- Linux：检测可用终端模拟器（gnome-terminal、konsole、xfce4-terminal、xterm），使用第一个可用的打开窗口；检测结果按进程缓存。
- 找不到终端时回退到无头后台执行。
- Windows 行为不变。

## 升级说明

使用以下命令升级：

```bash
npm install -g cli-wechat-bridge@latest
```

升级后，请重启正在运行的 bridge、daemon 和 companion 终端，让它们加载 1.0.9 runtime。

已经使用 scoped 包名的老用户也可以继续使用：

```bash
npm install -g @unlinearity/cli-wechat-bridge@latest
```

## 兼容性
