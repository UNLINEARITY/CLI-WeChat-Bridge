# 版本 1.1.3

**发布日期：** 2026 年 8 月 22 日

## 概览

1.1.3 将 Pi 作为与 Codex、Claude Code 和 OpenCode 并列的第四个原生 TUI adapter 接入。本版本同时刷新 Codex 与 OpenCode 对较新主流版本的兼容，改善 Windows 命令 shim 和 OpenCode 服务启动时序的可靠性，并让 daemon 用户可以在一条微信消息中完成 adapter 切换和 prompt 提交。

## 主要特性

### 原生 Pi TUI 桥接

- 新增 `wechat-bridge-pi`、`wechat-pi` 和 `wechat-pi-start`，将 Pi 接入独立 bridge、可见 companion 和单命令启动器工作流。`wechat-daemon` 也支持 `/pi`，并将 Pi 作为可复用的第四个 adapter slot。
- `wechat-pi` 通过继承终端输入输出启动用户真实的 Pi TUI，并注入带 token 认证的 localhost extension。本地键盘输入与微信 prompt 共用同一 Pi session，同时保留原生主题、快捷键、模型选择、extension UI 和完整本地用户权限。
- Pi 最终回复、本地 session 切换、`/stop`、`/new` 和 session 恢复通过结构化 extension 事件同步，不需要抓取或重绘一个替代终端。
- `wechat-pi-start` 默认新建 session；如需显式恢复上一个 session，使用 `wechat-pi-start --session-start-mode restore`。
- Pi 资源、模型或 extension 加载超过 30 秒时不再终止可见 TUI。bridge 会保持 `starting`，在已认证 extension 连接前继续等待，将早到命令排队到 Pi 发布 session context 之后，再转为 `idle`。

## 兼容性与工作流改进

### Codex app-server 兼容

- 移除已废弃的 `tui_app_server` feature 开关，并将 initialize 与 thread-start 请求对齐较新 app-server 协议。
- 新增返回整数 Unix 秒的 `currentTime/read` 处理，区分阻塞用户输入与带超时的非阻塞请求，并在 turn 完成、重置或停止时完整清理计时器。
- daemon 现在会等待可见 Codex 客户端发布其本地 thread，再转发行内或紧随 `/codex` 到达的微信 prompt。bridge 会将 turn 发送到该可见 thread，不再因与 `thread/start` 竞态而创建第二个隐藏回复 thread。
- 关闭本地 Codex 窗口后，daemon 不再继续使用陈旧的不可见 worker。下一条普通微信输入会重启 Codex runtime、打开新的可见终端，并等待其新本地 thread 就绪后再投递消息。
- 即使最后一条 `task_complete` JSONL 记录没有尾部换行，也会立即处理；已完成 turn 的迟到 RPC 通知会被忽略。这会防止已完成的微信 turn 被重新识别为本地 turn，并卡在 `codex is still working`。

### OpenCode 1.18 支持

- 将 OpenCode SDK 支持范围提升到 `>=1.18.0 <2.0.0`，通过 `/global/health` 验证服务器，并在 `opencode serve` 仍在启动时重试健康检查。
- 改用当前 `permission.reply` API，并归一化当前 global event 形态，不再启动 legacy 独立 sync loop。
- 将 `question.asked`、`question.replied` 和 `question.rejected` 映射到共享微信 `/answer` 工作流，保留问题顺序，支持单选、多选和自定义回答。`/stop` 会在中止 session 前先拒绝待处理 OpenCode 问题。

### Windows CLI 启动

- Windows 命令 shim（如 `claude.cmd`）现在会在 PTY 路径中被直接解析和启动，包括安装路径含空格的情况。

### 依赖安全

- 将 `@modelcontextprotocol/sdk` 升级到 `^1.30.0`，并刷新 npm 与 Bun lockfile，以选用已修复的 Hono、Express、Ajv、ESLint 支持包及相关间接依赖。刷新后依赖安全审计无已知漏洞。

### daemon 切换指令

- `/claude hi`、`/codex hi`、`/opencode hi` 和 `/pi hi` 现在会激活目标 adapter，再仅将 `hi` 转发给它。纯切换指令仍返回 adapter 状态，`/claudex hi` 等相似文本不会被误拦截。

## 升级说明

升级主包：

```bash
npm install -g cli-wechat-bridge@latest
```

已使用 scoped 包的用户可继续使用：

```bash
npm install -g @unlinearity/cli-wechat-bridge@latest
```

升级后，请重启所有正在运行的 bridge、daemon 和 companion 终端，使其加载 1.1.3 runtime。

## 兼容性

- 仍要求 Node.js `>=24.0.0`，源码与测试工作流继续使用 Bun。
- 本版本明确不支持低于 `1.18.0` 的 OpenCode 与未来 `2.x` 版本。
- Pi `0.84.2` 是已验证基线。bridge 使用 Pi 原生 TUI 和 extension API，不修改 Pi 上游源码。
- 不需要运行时数据迁移。
