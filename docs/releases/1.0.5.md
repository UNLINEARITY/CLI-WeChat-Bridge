# Version 1.0.5

**Release Date:** May 22, 2026

## Overview

Version 1.0.5 is the persistent daemon, migration, and npm package-name release. It adds `wechat-daemon` so a workspace can keep one long-lived WeChat connection while switching between Codex, Claude Code, and OpenCode from WeChat. The daemon reuses an existing visible CLI when it can, opens a new visible terminal when it has to, and keeps previous CLI slots alive during switching.

This release also makes `cli-wechat-bridge` the primary npm package name, keeps `@unlinearity/cli-wechat-bridge` as a compatibility mirror, moves runtime data to `~/.cli-bridge`, migrates existing users automatically from the old Claude-channel path, and saves inbound WeChat images and files to local paths that the selected CLI can inspect.

## Major Features

### Persistent daemon mode

- Added the `wechat-daemon` global binary and `npm run daemon` source command.
- Start the daemon once in a project directory, then switch from WeChat with `/codex`, `/claude`, or `/opencode`.
- Switching adapters keeps the previous CLI slot running instead of closing it.
- If the requested CLI already has a visible companion, the daemon switches back to it.
- If the requested CLI is missing, the daemon opens a new visible local terminal and waits for it to connect.
- `/status` reports the daemon workspace, active adapter, and slot states.
- `/daemon-stop` stops the long-lived daemon from WeChat.
- `wechat-codex-start`, `wechat-claude-start`, and `wechat-opencode-start` now delegate to a running daemon in the same workspace instead of fighting it.

### Short npm package name

- The primary npm package name is now `cli-wechat-bridge`.
- The scoped package `@unlinearity/cli-wechat-bridge` remains a compatibility mirror for existing users.
- Added a dual-package publish script that can publish the primary package and scoped mirror from the same build output.
- The global install smoke test now purges both package names before installing the current tarball, preventing old global shims from masking the active package.

### Automatic data migration to `~/.cli-bridge`

- The default channel data directory is now `~/.cli-bridge`.
- `CLI_BRIDGE_DATA_DIR` is the new active override for custom data directories.
- Existing data is migrated automatically from legacy WeChat channel directories on startup.
- Migrated data includes credentials, sync state, cached context tokens, update-check cache, workspace state, and inbound attachments.
- Existing files in the new directory are not overwritten.
- Old bridge locks are intentionally not migrated, so stale single-bridge state does not block the new runtime.
- Old `bridge.log` is preserved as `legacy-bridge.log` instead of being mixed into the new runtime log.

### Inbound WeChat attachments

- WeChat images and ordinary files received by the bridge are downloaded and saved under `~/.cli-bridge/inbound-attachments/<date>/`.
- The forwarded prompt includes the saved local paths so Codex, Claude Code, or OpenCode can read the files directly when the user asks for analysis.
- Attachment-only WeChat messages now produce a usable prompt instead of being dropped.
- Separate inbound download limits are available through `WECHAT_MAX_INBOUND_IMAGE_MB` and `WECHAT_MAX_INBOUND_FILE_MB`.
- Inbound message claims prevent duplicate processing across processes, with stale claims reclaimed automatically.
- Download failures are surfaced as prompt text so the selected CLI can explain what could not be read.

## Fixes

### Daemon startup cleanup

- Starting `wechat-daemon` now cleans stale single-bridge locks and companion endpoints before startup.
- If a live standalone bridge is already serving the same workspace, the daemon asks it to stop and waits for cleanup.
- If the old bridge ignores the graceful stop, the daemon force-cleans it before continuing.
- Standalone bridges now refuse to start over a live daemon, while stale daemon endpoints are cleared automatically.

### Visible CLI launch on Windows

- Daemon-managed visible terminals now launch through a Windows `start` command with the correct window title and working directory.
- Claude Code and OpenCode daemon companions no longer tell users to run a second terminal manually.
- The daemon waits for the visible CLI companion to connect before reporting the switch result.
- If the visible launcher times out, the daemon cleans up the launcher process and reports a clear status.
- Companion endpoint updates now preserve the visible companion PID after the hello handshake, preventing false daemon timeouts after Claude Code or OpenCode has already opened.

### WeChat context diagnostics

- `sendmessage` responses with `ret=-2` are now treated as stale WeChat context-token failures instead of retryable transport errors.
- Logs include the failed send context and recipient, making it clearer whether the failed message was a final reply, status update, or session switch notification.
- The bridge now tells the operator that the WeChat owner should send a fresh message first when the cached context token is stale.

## Improvements

- The daemon labels outgoing important messages with the active adapter, such as `[codex]`, `[claude]`, or `[opencode]`.
- Session switch events can be forwarded to WeChat for Claude Code and OpenCode in the same way as normal bridge status.
- Unknown starter arguments are forwarded to the visible local CLI, enabling workflows such as `wechat-codex-start --yolo` or `wechat-claude-start --dangerously-skip-permissions` without changing bridge-owned runtime settings.
- README now documents daemon mode, migration behavior, inbound attachments, the new data directory, and daemon CLI options.

## Upgrade Notes

Upgrade with:

```bash
npm install -g cli-wechat-bridge@latest
```

After upgrading, restart any running bridge, daemon, and companion terminals so they load the 1.0.5 runtime.

Existing scoped-package users can keep using:

```bash
npm install -g @unlinearity/cli-wechat-bridge@latest
```

Both package names expose the same `wechat-*` commands. Install only one globally at a time.

Existing users do not need to copy files manually. On first startup, the bridge migrates data from the old WeChat channel directory into `~/.cli-bridge` when the target files are not already present.

If you previously customized `CLAUDE_WECHAT_CHANNEL_DATA_DIR`, switch to `CLI_BRIDGE_DATA_DIR` for the active data directory. The old variable is only treated as a legacy migration source.

For long-lived multi-CLI use, start:

```bash
wechat-daemon
```

Then send `/codex`, `/claude`, or `/opencode` from WeChat.

## Compatibility

No breaking CLI command removals are expected. The package still requires Node.js `>=24.0.0`, and the test workflow still uses Bun.

The data directory changed from the old Claude-channel location to `~/.cli-bridge`, but the release includes automatic migration for existing users.
