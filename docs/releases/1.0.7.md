# Version 1.0.7

**Release Date:** May 26, 2026

## Overview

Version 1.0.7 is a daemon reliability, fresh-session startup, and documentation cleanup release. It hardens `wechat-daemon` so adapter switches do not corrupt the active terminal when a visible CLI fails to connect, lets Codex reconnect recover from missing endpoint files, and makes daemon startup clean up same-workspace daemon peers even when `daemon-endpoint.json` is missing or stale.

The release also makes Claude Code and OpenCode starter commands create fresh sessions by default, removes obsolete runtime paths that no longer belong to the daemon-first architecture, and moves detailed setup, configuration, troubleshooting, and development guidance into dedicated docs.

## Daemon Reliability Fixes

### Safer adapter switching

- `wechat-daemon` now activates a requested adapter only after the visible CLI is connected, or when visible startup was explicitly disabled.
- If `/codex`, `/claude`, or `/opencode` cannot connect the visible CLI, the daemon reports the failed activation and keeps the previous active adapter.
- Switch logs now include `activated`, `previous_active`, and `session_start_mode` fields so runtime failures can be diagnosed directly from `bridge.log`.
- Existing Codex slots now republish the local companion endpoint before opening a visible client, allowing `codex-remote-client` to recover when endpoint files were deleted.

### Startup cleanup and process takeover

- Daemon startup now cleans stale or still-running same-workspace `wechat-daemon` peer processes, even when `daemon-endpoint.json` is absent or points at the wrong process.
- Endpoint cleanup now also clears workspace companion endpoints for every daemon adapter.
- Forced cleanup avoids the current process and parent process and only force-stops endpoint PIDs when the process can be verified as a daemon or a shutdown request was acknowledged.
- Unit tests now inject daemon logging during cleanup so fake test process IDs no longer pollute the real `~/.cli-bridge/bridge.log`.

## Session Startup Improvements

### Claude Code and OpenCode fresh sessions

- `wechat-claude-start` and `wechat-opencode-start` now request a fresh session by default instead of silently restoring old shared-session state.
- Daemon-created Claude Code and OpenCode slots also default to fresh sessions unless an existing connected visible client is being reused.
- Same-workspace start requests for Claude Code and OpenCode can replace the existing companion-bound bridge when a fresh session is requested.
- Claude Code ignores saved resume IDs when a fresh start is requested, preventing stale transcripts from being resumed accidentally.
- OpenCode creates a new SDK session for fresh starts and passes both the target directory and active session route to the native attach client.
- OpenCode visible session selection now retries briefly after attach so the TUI follows the daemon-selected session more reliably.

### Claude workspace trust prompt handling

- Claude Code startup now marks the current workspace trusted in `.claude.json` when possible.
- If Claude still prints the workspace trust prompt during startup, the bridge auto-confirms it before user input starts.
- The auto-confirm path is disabled once a WeChat turn is active, so trust-looking text in normal output is not treated as a startup prompt.

## Cleanup And Documentation

- Removed obsolete standalone Claude bot code, legacy Codex panel IPC files, and the unused media transport abstraction.
- Removed direct `@anthropic-ai/sdk` and `ajv-formats` dependencies that were no longer imported by the active runtime.
- Added explicit Node type metadata for source checks.
- Added `CONTRIBUTING.md` with issue, PR, development, testing, and release guidance.
- Reworked the README around the user startup path and moved runtime configuration, troubleshooting, and development details into `docs/configuration.md`, `docs/troubleshooting.md`, and `docs/development.md`.
- Added a daemon multi-CLI screenshot to the README.

## Upgrade Notes

Upgrade with:

```bash
npm install -g cli-wechat-bridge@latest
```

After upgrading, restart any running bridge, daemon, and companion terminals so they load the 1.0.7 runtime. If an old daemon was left running from a previous version, starting `wechat-daemon` again in the same workspace should now clean it automatically.

Existing scoped-package users can keep using:

```bash
npm install -g @unlinearity/cli-wechat-bridge@latest
```

Both package names expose the same `wechat-*` commands. Install only one globally at a time.

## Compatibility

No new data migration is required. The package still requires Node.js `>=24.0.0`, and the source/test workflow still uses Bun.

The old standalone Claude bot and legacy Codex panel internals have been removed from the source tree. Published user-facing commands remain focused on Codex, Claude Code, OpenCode, and daemon workflows.
