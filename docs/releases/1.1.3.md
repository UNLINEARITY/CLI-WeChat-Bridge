# Version 1.1.3

**Release Date:** August 22, 2026

## Overview

Version 1.1.3 adds Pi as a first-class native TUI adapter alongside Codex, Claude Code, and OpenCode. It also refreshes Codex and OpenCode compatibility for newer mainstream releases, makes Windows and OpenCode startup more tolerant of real installation timing and command shims, and lets daemon users switch adapters and submit a prompt in one WeChat message.

## Major Features

### Native Pi TUI bridge

- New `wechat-bridge-pi`, `wechat-pi`, and `wechat-pi-start` commands integrate Pi into standalone bridge, visible companion, and one-command launcher workflows. `wechat-daemon` also accepts `/pi` and keeps Pi as a reusable fourth adapter slot.
- `wechat-pi` launches the user's real Pi TUI with inherited terminal input/output and injects a token-authenticated localhost extension. Local keyboard input and WeChat prompts share the same Pi session while native themes, shortcuts, model selection, extension UI, and full local-user permissions remain available.
- Pi final replies, local session changes, `/stop`, `/new`, and session restoration are synchronized through structured extension events instead of scraping a replacement terminal renderer.
- `wechat-pi-start` creates a fresh session by default. Use `wechat-pi-start --session-start-mode restore` to explicitly restore the previous session.
- Slow Pi resource, model, or extension loading no longer terminates the visible TUI after 30 seconds. The bridge remains in `starting` state until the authenticated extension connects, queues early commands until Pi publishes its session context, and then transitions to `idle`.

## Compatibility and Workflow Improvements

### Codex app-server compatibility

- Removed the retired `tui_app_server` feature flag and aligned initialize and thread-start requests with the newer app-server protocol.
- Added `currentTime/read` handling with whole Unix seconds and separated blocking user-input requests from timed non-blocking requests, including complete timer cleanup when turns end, reset, or stop.
- Daemon activation now waits for the visible Codex client to publish its local thread before forwarding an inline or immediately following WeChat prompt. The bridge then sends the turn to that visible thread instead of racing `thread/start` and creating a second hidden reply thread.
- Closing the local Codex window no longer leaves the daemon on a stale invisible worker. The next ordinary WeChat input restarts the Codex runtime, opens a new visible terminal, and waits for its new local thread before dispatching the message.
- Complete `task_complete` JSONL records are processed even when the final line has no trailing newline, and late RPC notifications from completed turns are ignored. This prevents a finished WeChat turn from being reclassified as a local turn and getting stuck on `codex is still working`.

### OpenCode 1.18 support

- Raised the supported OpenCode SDK line to `>=1.18.0 <2.0.0`, validates the server through `/global/health`, and retries health probes while `opencode serve` is still starting.
- Uses the current `permission.reply` API and normalizes current global event shapes without the legacy standalone sync loop.
- Maps `question.asked`, `question.replied`, and `question.rejected` into the shared WeChat `/answer` workflow, preserving question order and supporting single-select, multi-select, and custom responses. `/stop` rejects a pending OpenCode question before aborting the session.

### Windows CLI startup

- Windows command shims such as `claude.cmd` are resolved and launched directly through the PTY path, including installations under directories containing spaces.

### Dependency security

- Updated `@modelcontextprotocol/sdk` to `^1.30.0` and refreshed both npm and Bun lockfiles so patched Hono, Express, Ajv, ESLint support packages, and related transitive dependencies are selected. The dependency audit reports no known vulnerabilities after the refresh.

### Daemon switch directives

- `/claude hi`, `/codex hi`, `/opencode hi`, and `/pi hi` now activate the requested adapter and forward only `hi` to it. Bare switch commands still return adapter status, and similar text such as `/claudex hi` is not intercepted.

## Upgrade Notes

Upgrade the primary package with:

```bash
npm install -g cli-wechat-bridge@latest
```

Existing scoped-package users can continue with:

```bash
npm install -g @unlinearity/cli-wechat-bridge@latest
```

After upgrading, restart every running bridge, daemon, and companion terminal so it loads the 1.1.3 runtime.

## Compatibility

- Node.js `>=24.0.0` remains required, and the source/test workflow continues to use Bun.
- OpenCode versions older than `1.18.0` and future `2.x` releases are intentionally unsupported by this release.
- Pi `0.84.2` is the tested baseline. The bridge uses Pi's native TUI and extension API and does not modify the upstream Pi source.
- No runtime data migration is required.
