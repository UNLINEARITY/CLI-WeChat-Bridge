# 版本 1.0.4

**发布日期：** 2026 年 5 月 16 日

## 概览

1.0.4 是一次面向 bridge 回复可靠性和发布可信度的更新。这个版本让 OpenCode 与 Codex 回传到微信的内容更接近本地终端里真正可见的回复，避免启动时把历史本地 session 内容重新发到微信，并补上发布前需要的质量门禁与真实全局安装烟测。

这个版本同时刷新 README，补齐当前 npm 工作流、单命令启动器、OpenCode 支持和贡献者验证路径。

## 修复内容

### OpenCode 回复正确性

- OpenCode final reply 现在优先读取 session 中最新的可见 assistant 回复，而不是只取 500 字符输出尾部摘要。
- 较长的 OpenCode 可见回复仍会作为一整条微信文本发送，保留与本地终端更一致的阅读体验。
- OpenCode 的 reasoning-only part 与 reasoning 文本 delta 会在回传微信前被忽略。
- 本地 prompt 回显和微信来源 prompt 回显不会进入最终回复缓存，避免把用户输入混进 assistant 回复。
- 如果 OpenCode 只产生了会被可见回复清洗规则移除的内容，微信会收到清晰的诊断提示，而不是静默无回复或返回误导性内容。

### Codex 启动与 session 隔离

- 只有 adapter 和工作区都与持久化状态一致时，才会恢复 shared session。
- 在 OpenCode session 之后启动 Codex 时，不再恢复 OpenCode 风格的 `ses_...` shared session id。
- Codex 启动且没有活跃微信 turn 时，会设置 session replay 截止点，避免历史本地 `mirrored_local_input` 或 `final_reply` 事件被重新发到微信。

## 改进内容

### 源代码质量门禁

- 新增覆盖 `bin`、`src` 和 `test` 的 ESLint flat config。
- 新增 `npm run lint`、`npm run lint:fix`、`npm run typecheck:src` 和 `npm run quality`。
- `npm run quality` 现在会依次运行 lint、源代码 TypeScript 检查、完整 Bun 测试和 build。
- 新增只检查源代码的 TypeScript 入口，让严格类型错误在发布构建之外也能被稳定暴露。
- 清理 bridge adapters、companion startup、WeChat transport 和 update checking 中已有的源代码 TypeScript 错误。
- 为缺失 TypeScript 类型的 `qrcode-terminal` 增加本地声明。

### Bridge adapter 清理

- 将通用 bridge adapter helper 抽入 `src/bridge/bridge-adapter-common.ts`。
- 保留 `bridge-adapters.shared.ts` 的 re-export 调用面，避免破坏现有 imports。
- 收紧 Codex、Claude、OpenCode、shell 和 shared bridge helper 中的元数据、空值访问与事件形态处理。

### 真实全局安装烟测

- 新增 `npm run smoke:global`，用于发布前和人工验证。
- 脚本现在会把当前源码打成真实 npm tarball，并通过 `npm install -g` 安装到真实全局环境。
- 安全的全局命令 shim 会从用户主目录通过真实 shell `PATH` 验证，包括 Windows PowerShell shim 解析。
- `--purge-global` 会在测试前卸载当前全局包。
- `--clean-cache` 会在打包和安装前清理 npm 缓存。
- `--full` 会在烟测前运行完整质量门禁。
- `--keep-tarball` 会保留生成的 tarball 便于排查。
- 如果 npm 已安装 shim 但当前 shell 无法解析命令，脚本会报告清晰的 PATH 错误，而不是通过一个误导性的临时 prefix 测试。

### 文档刷新

- README 现在记录当前 npm 安装路径、全局 `wechat-setup`、单命令启动器和手动双终端调试模式。
- OpenCode 已与 Codex、Claude Code 和 shell 一起列入受支持 adapter。
- 新增 README 媒体素材，让项目用途和运行流程更容易识别。
- 移除了已经不再符合当前多 adapter 工作流的旧 Codex 单独说明。

## 升级说明

1.0.4 发布后，使用以下命令升级：

```bash
npm install -g @unlinearity/cli-wechat-bridge@latest
```

升级后，请重启正在运行的 bridge 和 companion 终端。

如果要从源码做发布前或本地全局验证，运行：

```bash
npm run quality
npm run smoke:global -- --purge-global --clean-cache
```

`npm run smoke:global` 会有意修改真实 npm 全局安装状态。它适用于你希望把本地构建出的包保留在全局环境中，继续做后续人工验证的场景。

## 兼容性

本次预计没有破坏性变更。包仍要求 Node.js `>=24.0.0`，测试工作流仍需要 Bun。
