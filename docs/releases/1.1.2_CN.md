# 版本 1.1.2

**发布日期：** 2026 年 7 月 7 日

## 概览

1.1.2 是可靠性与跨平台安装版本。修复 node-pty 预编译 spawn-helper 二进制缺执行位导致 macOS/Linux 静默 fallback 到非 PTY 模式的问题；为每个 adapter 加入崩溃防护和 turn 完成竞态守卫；共享状态改为原子写入、入站去重改为 fail-closed；恢复被过严白名单丢弃的 Windows 环境变量；重写更新检查改用 npm registry，让全局安装不再依赖 git 仓库；并新增三平台 CI 质量门禁。

## 改进

### 跨平台安装（node-pty）

- 新增 `postinstall` 脚本恢复 node-pty 预编译 spawn-helper 二进制的执行位（发布 tarball 里权限为 `0644`，缺执行位）。此前 macOS/Linux 上 `posix_spawnp` 失败、bridge 静默 fallback 到非 PTY 模式，Claude 甚至报 `Error: Input must be provided ... when using --print`，而 `--doctor` 仍显示 node-pty 已加载——因为 doctor 只检查 `require`，不检查实际 fork。脚本幂等、永不中断安装。
- postinstall 脚本本身已纳入发布的 `files` 字段，修复 `npm install -g` 时的 `MODULE_NOT_FOUND`。

### 可靠性与崩溃修复

- OpenCode turn 完成加入单调 turn token 守卫，陈旧的延迟完成不再覆盖新启动的 turn（不再把状态翻回 idle、发旧 `final_reply`、清空新 turn 缓冲）。
- Codex app-server spawn 失败不再崩溃 bridge，子进程挂上了 error handler。
- Claude 的 invalid-resume 恢复改为捕获失败并 emit `fatal_error`，不再留 unhandled rejection；Claude hook TCP 行缓冲加 1 MiB 上限。
- PTY fallback 路径把 spawn 错误（`ENOENT`/`EACCES`）转为 exit 上报，并吞掉子进程退出后的 stdin broken-pipe；detached 后台 bridge spawn 补上对应的 error handler。
- POSIX 进程树终止改用 `pgrep` 遍历后代并叶子优先 kill，修复未 detached 进程组下 Codex/OpenCode 孙进程在 Linux/macOS 上被托孤给 init 的问题。

### 状态持久化与入站去重

- 共享状态（`context_tokens.json`、`bridge-state`、`bridge-lock`）改为通过临时文件 + rename 原子写入，避免崩溃时留下半写文件破坏下次启动或被误判为 stale lock。
- 入站消息 claim 在非 `EEXIST` 文件系统错误时 fail closed（返回 `false` 而非不写 claim 文件就声称持有），防止并发进程重复处理同一消息。claim 清理改为基于 `readdir` 快照逐文件删除，而非可能误删并发刚建 claim 的 `rmdir`。
- bridge.log 增长用共享 `appendBoundedLog` 限制（5 MiB 上限，超限保留尾部一半），并为更新检查的 `setTimeout` 加 unref，避免挂活 event loop 与强制退出 teardown 竞态。`getUploadUrl` 包裹 `JSON.parse`，200 但非 JSON 的响应不再抛出未分类的 `SyntaxError`。

### 环境与消息处理

- Windows 不再丢弃 `ANTHROPIC_BASE_URL` 和 `OPENAI_API_KEY`：子进程现在收到完整 `process.env`，而非过严的白名单。
- 消息启动 grace 窗口从 5s 扩大到 30s 吸收时钟偏差，无时间戳的消息被视为新消息而非丢弃。
- 长回复按 1200 字符分段（换行感知），final reply 不再因过长被微信服务器拒绝。
- 附件绝对路径判断改用平台无关正则，同时识别 Windows 盘符路径（`C:\`、`C:/`）、POSIX 根路径（`/`）和 UNC 路径，且不再把分隔符统一为 `path.sep`——修复 Linux/macOS 上 Windows 盘符路径被改写后遭拒导致的附件静默丢弃。这正是非 Windows CI runner 上附件测试通过的原因。
- doctor 诊断新增与微信服务器的时钟偏差检测、Windows 代码页检查和代理环境变量检查。
- 新增 `CLI_BRIDGE_STRICT_APPROVAL` 严格审批模式，禁用所有自动审批并把每个权限请求强制转发到微信。

### 更新检查

- `wechat-check-update` 改为查询 npm registry（回退 GitHub tags API），不再用 `git ls-remote --tags`，因此非 git 仓库的全局安装也能工作。
- 所有 `process.exit()` 替换为 `process.exitCode` + 自然 return，修复 Windows + Node 24 上强制退出与 undici handle 关闭竞态导致的 libuv `UV_HANDLE_CLOSING` 断言崩溃。新增 `parseVersion`（兼容 v 前缀）和 16 个测试。

### CI 与贡献者体验

- 新增 GitHub Actions 质量门禁：在 PR 与 push 到 `main` 时于 Ubuntu/macOS/Windows 三平台跑 lint + typecheck + test + build（`fail-fast` 关闭，因为 node-pty spawn-helper 行为因平台而异）。Bun install 按 `bun.lock` 缓存。
- 双语 PR 模板带三项自查（完整规范在 `CONTRIBUTING.md`），README 增加 CI 状态徽章。

## 升级说明

使用以下命令升级：

```bash
npm install -g cli-wechat-bridge@latest
```

升级后，请重启正在运行的 bridge、daemon 和 companion 终端，让它们加载 1.1.2 runtime。

已经使用 scoped 包名的老用户也可以继续使用：

```bash
npm install -g @unlinearity/cli-wechat-bridge@latest
```

## 兼容性

本版本不需要新的数据迁移。包仍要求 Node.js `>=24.0.0`，源码和测试工作流仍使用 Bun。node-pty 的 postinstall 执行位修复会在每次安装时运行（幂等、永不中断安装）。
