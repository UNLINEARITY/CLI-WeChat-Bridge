# Version 1.2.0

**Release Date:** September 21, 2026

## Overview

Version 1.2.0 opens the daemon to external programs through an authenticated local IPC interface, adds the `/all` command for broadcasting one prompt to every running CLI, shows the native "typing…" indicator in WeChat while a remote turn runs, and aligns reply delivery with the official WeChat bot client. The product site is rebuilt around the native two-way workflow, and licensing is strengthened across the codebase. 154 files changed with 5,371 insertions and 1,164 deletions since 1.1.8.

## Daemon IPC for External Programs

`wechat-daemon` and `wecom-daemon` now expose a token-authenticated local IPC interface. External tools — web panels, scripts, or your own bot frontends — can drive the daemon the same way chat messages do:

- `forward_input` routes text to any adapter slot through the exact same gating as inbound chat: busy rejection, pending approval and structured-input waits, and automatic Codex queueing during local turns. Requests are serialized per CLI, replies stay bound to the requesting conversation, and turn state plus the active adapter roll back when an input is rejected or fails.
- `send_text` borrows the daemon's channel to deliver a message, with typed and validated context values.

The semantics are documented in `docs/development.md`.

## `/all` Broadcast Command

Send `/all <prompt>` from WeChat or WeCom to dispatch the same prompt to every started CLI at once. Adapters that are not running are listed as skipped with a hint on how to start them. If any started worker is busy — mid-task, awaiting approval, awaiting structured input, or with queued inputs — the whole broadcast is canceled with a clear notice instead of partial delivery. Replies keep their per-adapter prefix and the active adapter stays unchanged.

## WeChat "Typing…" Indicator

While a CLI works on a prompt dispatched from WeChat, the chat shows the native "typing…" indicator, kept alive with a five-second heartbeat and cleared when the reply is delivered, the task fails, or the daemon shuts down. Typing tickets are fetched per recipient from the official WeChat config endpoint, cached with a random 24-hour refresh and exponential-backoff retry, and the whole indicator degrades silently when no ticket is available — message flow is never affected. The hooks live on the channel driver, so other channels are untouched.

## Reply Delivery Improvements

- Long replies now go out as one complete message instead of being split at 1,200 characters, matching the official WeChat bot client, which posts the full text in a single sendmessage call. If the server ever rejects an oversized message, the existing retry, logging, and pending-queue handling still reports the failure instead of losing the reply silently.
- The pending-queue keeps only delivery-worthy contexts — final replies, approval and structured-input requests, and failure notices; mirrored input, notices, and session-switch chatter are dropped. Entries older than thirty minutes expire and the backlog is capped at ten messages, so reconnecting after a token outage delivers at most the recent important replies instead of replaying hours of history.

## Product Site Rebuild

The GitHub Pages product site is rebuilt around the native two-way workflow between WeChat or WeCom and local CLI sessions: Chinese and English routes, an interactive channel-to-bridge-to-CLI architecture diagram, capability and trust sections, a channel-aware rotating command builder, and a capture carousel with responsive and reduced-motion behavior. Site metrics refresh daily and the site redeploys automatically when the package version changes.

## Licensing Strengthened

Every source file now carries an SPDX AGPL-3.0-or-later header with the copyright holder's contact address and the repository URL, stating that modifications and derivative works must ship complete source under the same license and that network services built on the bridge must offer source to their users. The README license section spells out the same obligations explicitly for AI-assisted modifications, and the repository guidelines require the headers to be preserved in every new and modified file.

## Important Notes and Upgrade

The minimum Node.js version remains 22.13.0; using the Pi adapter requires 22.19.0 or newer. Upgrade with:

```bash
npm install -g cli-wechat-bridge@latest
```

Scoped-package users upgrade with:

```bash
npm install -g @unlinearity/cli-wechat-bridge@latest
```

Restart running bridge, daemon, and visible CLI processes after upgrading. The IPC interface is enabled by default on running daemons; see `docs/development.md` for the endpoint and token location. No migration steps are required.
