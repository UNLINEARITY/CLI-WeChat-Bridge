# Version 1.0.8

**Release Date:** May 26, 2026

## Overview

Version 1.0.8 adds WeChat emoji-to-command bindings, a new feature that lets users trigger daemon commands by sending WeChat stickers. It also includes runtime bug fixes for process lifecycle, resource safety, Claude hook coverage, and visible terminal support on macOS and Linux.

## New Feature: Emoji Bindings

### Default bindings

Six default emoji-to-command mappings are provided out of the box:

| Emoji | Command | Description |
|-------|---------|-------------|
| `[OK]` | `/confirm` | Approve permission requests |
| `[闭嘴]` | `/stop` | Interrupt current task |
| `[拥抱]` | `/claude` | Switch to Claude Code |
| `[强]` | `/codex` | Switch to Codex |
| `[胜利]` | `/opencode` | Switch to OpenCode |
| `[再见]` | `/daemon-stop` | Stop daemon |

### Management commands

Users can manage bindings directly from WeChat:

- `/bindings` — list all current bindings
- `/bind [emoji] /command` — bind an emoji to a command
- `/unbind [emoji]` — remove a binding

### Behavior

- Emoji must appear at the start of the message to trigger (prefix-only matching).
- When an emoji resolves to a switch command with trailing text (e.g. `[拥抱]帮我写个脚本`), the adapter is switched first, then the remainder is forwarded as a message to the new adapter.
- Matching is case-insensitive (`[OK]` equals `[ok]`).
- Bindings persist to `~/.cli-bridge/emoji-bindings.json` and survive daemon restarts.
- Runtime matching is zero-IO: the config is loaded into an in-memory Map at daemon startup; modifications update the Map synchronously and write to disk asynchronously.

## Bug Fixes

### Stop-resume deadlock

- Claude adapter's `interrupt()` now calls `scheduleTaskComplete()` with a 1.5s fallback timeout, preventing the adapter from permanently stuck in "busy" state when the Stop hook never fires.

### WeChat image visibility

- Inbound attachment prompts rewritten with imperative ACTION REQUIRED language, forcing Claude to Read image files before responding.

### Daemon session takeover

- Daemon startup captures the result of `cleanupSingleBridgeBeforeDaemon()` and uses `session_start_mode=restore` when creating a slot for the same adapter that was just killed, preserving the interrupted conversation.

### Process lifecycle and resource safety

- POSIX process tree termination now kills the entire process group via negative PID.
- PTY dispose awaits process exit with a 3s timeout to prevent race conditions.
- Daemon signal handlers use a reentrant guard with forced exit on second signal.
- Windows cleanup uses `taskkill` directly instead of ineffective SIGTERM.
- 30s timeouts added to companion and Codex RPC requests.
- Orphaned pending requests are rejected on socket disconnect.
- IPC buffers capped at 1MB to prevent DoS.
- Session log polling switched to incremental reads.
- Unsafe `proc.pid!` assertions replaced with null guards.

### Claude hook coverage

- Hook event coverage expanded from 6 to 11 events (adding PreToolUse, PostToolUse, PreCompact, PostCompact, SubagentStop).
- PostCompact handled as the reliable compact-completion signal.

## Visible Terminal on macOS and Linux

- macOS: uses `osascript` to open Terminal.app with the companion command.
- Linux: detects available terminal emulators (gnome-terminal, konsole, xfce4-terminal, xterm) and opens the first one found; detection result is cached per process.
- Falls back to headless background execution when no terminal is available.
- Windows behavior is unchanged.

## Upgrade Notes

Upgrade with:

```bash
npm install -g cli-wechat-bridge@latest
```

After upgrading, restart any running bridge, daemon, and companion terminals so they load the 1.0.8 runtime.

Existing scoped-package users can keep using:

```bash
npm install -g @unlinearity/cli-wechat-bridge@latest
```

## Compatibility

No new data migration is required. The package still requires Node.js `>=24.0.0`, and the source/test workflow still uses Bun.
