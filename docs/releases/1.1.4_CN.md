# 版本 1.1.4

**发布日期：** 2026 年 8 月 23 日

## 概览

1.1.4 将启动方式收拢为四条命令（`wechat-codex`、`wechat-claude`、`wechat-opencode`、`wechat-pi`）：一条命令完成微信凭据校验、daemon 委托与本地桥接拉起，不再需要单独的 bridge 命令。本版本同时集中修复了全面代码审查发现的二十余处并发与稳定性缺陷，其中包括一个自首个版本起即导致 Windows 上多项保护机制失效的进程扫描缺陷。OpenCode 方面补齐两项能力：agent 提问可在微信中直接作答，`/resume` 可恢复历史会话。

## 启动方式

四个直接命令成为完整的启动入口：运行后先校验微信登录，同目录存在运行中的 daemon 时委托其处理，否则在本地启动一个随终端关闭而停止的桥接。原 `wechat-bridge*` 系列命令全部移除，其功能并入这四条命令。`wechat-*-start` 命令仍可使用，将于 1.1.5 移除。独立桥接发送到微信的欢迎消息精简为两行，daemon 启动时保留完整的命令与 emoji 参考。

## 稳定性

进程相关判定改为先核实身份再执行。此前仅依据进程号：当操作系统将已退出桥接的进程号重新分配给无关程序时，新桥接会因锁冲突无法启动并给出指向不明进程的错误，进程清理逻辑也存在误终止无关程序的风险。现在锁回收、孤儿清理与父进程监视均先比对进程命令行，确认目标确属桥接后才执行操作。Windows 上另修复一个更基础的缺陷：进程扫描的 PowerShell 语句缺少分隔符，自首个版本起每次扫描均解析失败并返回空结果，导致 peer 检测、孤儿清理与 daemon 身份确认在该平台从未实际生效。

daemon 在并发下保持一致。此前微信消息、IPC 请求与启动流程可能同时请求创建同一适配器，导致重复终端、重复回复与状态文件相互覆盖；同类请求现已按适配器排队执行。输入等待路径同步修正：agent 发起选择或表单请求后，过早到达的回复此前会绕过登记直接写入终端，现在请求在事件到达时立即登记，快速回复可以正确匹配。`--session-start-mode new` 在 codex 上正式生效——此前该参数或被忽略，或作为未知参数传给 codex 客户端导致启动失败。daemon 异常退出时不再遗留子进程，崩溃的适配器由下一条切换指令重建，`/answer` 与 `/confirm`、`/deny` 一致地跨会话定位等待回复的目标。

向 daemon 委托启动的时序得到修正。此前冷启动几乎必然在两秒处超时退出，而 daemon 实际仍在处理并在此后打开终端，用户看到的失败对应的是一次成功的启动；等待期限现调整为 45 秒，daemon 确认失败时启动器退回本地启动，不再直接中止。

各适配器的异常恢复与其真实故障模式对齐。OpenCode 流式输出不再丢失内容（重复单词、表格分隔符此前被误判为重发数据而丢弃）；Pi 在扩展连接断开后可恢复而非永久停留在 busy 状态，意外退出上报为致命错误；Codex 在意外重连后立即重新订阅共享线程，挂起中的审批不再无法应答；同一目录运行两个 Claude 桥接不再相互覆盖审批配置。`/stop` 打断等待审批的 Claude 后状态正确清理，被中断的 Codex 回合不再在稍后产生重复回复。

共享状态与网络请求的超时保护完整覆盖。桥接与终端共享的状态文件改为原子写入，写入中断不再使另一侧将健康桥接误判为缺失；微信接口请求自建立到响应体读取完毕全程受超时约束，不再因服务端停滞而无限挂起。终端启动期间到达的消息等待其就绪后投递，不再报 "not ready" 错误；长回复投递中断时，明确告知未送达的分段与附件数量。

## OpenCode

agent 通过提问功能请求用户输入时，此前无法从微信作答；现在 `/answer` 的回复可完整送达 OpenCode。每个启动的 opencode 服务均注入一次性随机密码，SDK 客户端与健康探测携带对应凭证，本机其他进程无法再连接并操控该服务。retry 状态按忙碌处理，双事件流按服务器帧标识去重，目录匹配在 POSIX 主机同样成立。微信 `/resume` 可列出并恢复当前目录的最近会话，可见终端同步切换。

## 附件与安装

自动发送附件的规则调整为：agent 回复中提及的普通文件（源码、文档、压缩包）照常自动上传，可执行程序与安装包（`.exe`、`.dll`、`.bat`、`.ps1`、`.sh` 等）不再自动上传。镜像包 `@unlinearity/cli-wechat-bridge` 恢复随包发布安装脚本，macOS 与 Linux 安装后 PTY 适配器恢复正常。

## 升级说明

主包升级：

```bash
npm install -g cli-wechat-bridge@latest
```

现有 scoped 包用户继续使用：

```bash
npm install -g @unlinearity/cli-wechat-bridge@latest
```

升级后请重启所有运行中的 bridge、daemon 与终端。脚本或命令历史中残留的 `wechat-bridge*` 命令请替换为对应的直接命令；`wechat-*-start` 在本版本仍可用，下个版本移除。

## 兼容性

仍要求 Node.js `>=24.0.0`。OpenCode 支持 `>=1.18.0 <2.0.0`（已在 1.18.18 与 1.18.21 上验证）。旧的 `claude-runtime/` 目录已被按实例区分的目录取代，可手动删除；无需数据迁移。
